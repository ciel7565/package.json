# 전통발효체험관 메타버스 — 아키텍처 (PHASE 01 산출물 요약, 6단계 반영)

원본 기획서(PHP + HTML + CSS + JS + Three.js 마스터 프롬프트, AI 단계별 개발 지시서)의 요구를
**브라우저 단일 HTML + 선택형 PHP 서버** 구조로 구현했습니다. 6단계(CONTRACT §14)에서 서버는 사용자의 호스팅
(Apache 2.4 Win32 · PHP 7.2 · MariaDB 10.3)에 맞춰 이식되었고, 구독(토스페이먼츠)·더블 점프·2배 기본 속도·
검정 화면 가드·옛 놀이 표현 정리(만장대 시작 버튼)·최적화가 더해졌습니다.

## 1. 전체 구조

```text
┌──────────────────────────── Browser (index.html 한 파일) ───────────────────────────┐
│  HTML + CSS  : HUD(프로필·메뉴·미니맵·퀘스트·채팅·하단바), 모달, 대화창, 사진 모드        │
│  JavaScript  : G 네임스페이스 + 시스템(퀘스트·농사·발효·교육·일기·도감·날씨·채팅·구독…)   │
│  Three.js    : 3D 월드(지형·강·건물·장독대·작물·아바타·NPC·날씨 효과) — WebGL2/GPU       │
│                + 화면 가드(G.gfx.guard)·검정 블록 워치독 — 3D 불가 기기는 2D 전용 모드    │
│  Storage     : localStorage (로컬 모드)  ─ 또는 ─  fetch → PHP API (서버 모드)          │
└───────────────────────────────────────────────┬────────────────────────────────────┘
                                                │ HTTPS / JSON (선택)
                                   ┌────────────▼────────────┐      ┌──────────────────┐
                                   │ PHP ≥ 7.2 REST API      │◄────►│ 토스페이먼츠 API   │
                                   │ (Apache 2.4 · XAMPP)    │      │ confirm/billing/   │
                                   │ 인증·세션·CSRF·저장 검증   │      │ webhook (mock 가능)│
                                   │ 채팅·접속자·업로드·구독    │      └──────────────────┘
                                   └────────────┬────────────┘
                                   ┌────────────▼────────────┐
                                   │ SQLite(기본) / MariaDB   │ users, player_saves, chat…, subscriptions,
                                   │ 10.3 · MySQL             │ orders, payment_events
                                   └─────────────────────────┘
```

- 원칙(기획서 #9, #62, #153): **3D = Three.js / UI = HTML·CSS / 체험 데이터 = PHP·DB(서버 모드)**
- 단일 파일이 필요한 이유: 설치·서버 없이 더블클릭 실행 (기획서 #123 "파일 업로드 → 실행"). 같은 HTML이
  서버 모드의 `index.html`이기도 합니다(결제 SDK는 서버 모드에서 어른이 눌렀을 때만 불러옵니다).

## 3. 데이터 흐름

- 시스템은 `G.register({name, order, init, onStateLoaded, update, onLogout})`로 등록 → 로딩 화면에서 순서대로 초기화.
  `G.initSystems`는 결과 `G.bootReport {failed, critical, unsupported}`를 돌려주고 `core:init`을 냅니다.
  엔진·플레이어처럼 없으면 놀 수 없는 시스템이 실패하면 `engine:unsupported`로 알리고(10-engine의 WebGL2 탐지와
  같은 통로), 70-app이 "이 기기에서는 3D를 열 수 없어요" 화면(2D 전용 모드 선택)을 보여 줍니다. 아무도 화면을
  띄우지 않으면 00-core의 부팅 가드가 어른용 안내 카드를 띄워 아이가 죽은 월드에 들어가지 않게 합니다.
- 시스템 간 통신은 **이벤트 버스**(`G.bus.emit('farm:harvested', …)`) — 퀘스트·업적·도감·통계는 이벤트를 구독해 갱신.
- 저장 상태 `G.state`는 각 시스템이 자기 영역만 수정 후 `G.dirty()` → 1.5초 디바운스 저장 + 30초 자동 저장 + 창 닫힘 시 저장.
- 시간 기반(작물 성장·발효)은 `G.time.now()` 타임스탬프로 계산 → 접속하지 않은 동안의 시간도 반영(최대 1시간).
  서버 모드에서는 서버 시계 기준(기획서 #97).
- **속도 단계(6단계):** 서버(`auth/me`·`login`·`player/get`)가 알려 주는 `sub {tier, status, expiresAt}` →
  `G.sys.speed.setFromServer()` → `speed:changed {tier, prev}` → 플레이어 이동(최대 3배)·작물 성장·발효 진행(최대 4배)이
  매 프레임 `G.sys.speed`를 읽습니다. 아이를 보호하는 시간(건강한 놀이 타이머·어른 확인 대기·채팅 제한)은 빨라지지 않습니다.
  로컬 모드는 항상 1단계이며 클라이언트의 `sub` 값은 서버가 저장 시 무시합니다(서버가 기준).
- **결제(서버 모드):** 어른 확인 → 72-subscription `prepare` → 토스 결제창(또는 mock 테스트 결제) → `return.php`가
  `confirm`/`billing-issue` → `subscriptions`·`orders` 갱신 + 감사 로그 → `?sub=ok`로 돌아와 상태 재조회.
  자동 갱신은 `cli/tfm.php sub:renew`(작업 스케줄러) 또는 로그인 시 1시간 1회의 지연 갱신 검사가 처리합니다.

## 4. 서버 모드 보안 (기획서 #57–60, #98–104)

- PDO Prepared Statement, `password_hash/verify`(ARGON2ID → ARGON2I → BCRYPT 순으로 가능한 것), 세션 쿠키
  HttpOnly·SameSite=Lax·(HTTPS 시) Secure — PHP 7.2에서는 `Cookie::session()/set()`이 헤더를 직접 씁니다 —,
  CSRF 토큰, 요청 빈도 제한, 업로드 MIME·크기·확장자 검사 및 파일명 무작위화, 모든 상태 변경에 감사 로그.
- **치팅 방지**: 클라이언트가 보낸 저장 데이터를 서버가 직전 저장본과 비교해 코인·경험치 증가량이
  보상표(퀘스트·업적·퀴즈·수확·발효·판매)를 넘으면 거부(409)하고 서버 저장본으로 되돌림. 수확 시점도 서버 시간으로 검사.
  이동·발효·성장 속도 한계는 그 계정의 구독 단계에 맞춰 계산합니다.
- **결제 안전**: 금액은 서버가 저장한 주문과 정확히 일치해야 하고, 이미 승인된 주문(재전송)과 남의 주문은 거부합니다.
  웹훅은 본문을 믿지 않고 토스 API를 다시 조회해 확인하며 단계를 올릴 수는 없습니다. 비밀 키는 서버 설정에만 있고
  로그에 남기지 않습니다. 구독 화면·가격은 쉬운 모드에서 어른 확인(parent gate)을 통과해야만 보입니다.
- 로컬 모드는 서버가 없으므로 클라이언트 저장이 전부입니다(오프라인 체험판). 운영 시 서버 모드를 사용하세요.

## 5. 성능 (기획서 #69, #148)

인스턴싱(나무·장독·풀·작물), 정적 지오메트리 병합, 공유 재질, 그래픽 품질 프리셋(낮음/중간/높음)과
FPS 기반 자동 하향, 그림자 카메라 플레이어 추적, 원거리 체험객 업데이트 간격 축소, 라벨 거리 컷, 거리 컬링.
6단계: 빌드 시 스크립트 압축(esbuild, `--dev`는 원본 유지), 셰이더 사전 컴파일(로딩 화면 뒤), 첫 프레임 뒤로 미루는
무거운 초기화, 핫 패스의 프레임당 할당 제거, 로그아웃 시 정리(dispose). 화면 가드/워치독은 2초마다 96×54 축소 화면을
읽어 큰 검정·흰 블록을 찾고 단계적으로(효과 숨김 → 후처리 끔 → 캔버스 텍스처 숨김 → 낮음 프리셋) 격리합니다.

## 7. 알려진 한계

- 3D 모델은 코드로 만든 절차적(블록아웃+디테일) 모델입니다. GLB 교체 훅(`G.data.modelOverrides`)으로 고품질 모델로 바꿀 수 있습니다.
- 실시간 WebSocket 대신 폴링(일정 간격 조회) 방식 — 일반 PHP 호스팅 호환(기획서 #55 기본 버전).
- 음성 채팅(WebRTC)은 미포함, 대신 음성 인식으로 채팅 입력(Web Speech API, 브라우저 지원 시).
- 3D 월드는 WebGL2가 필요합니다(three r170). WebGL1만 되는 기기는 2D 전용 모드(배움터·일기·설정·도움말)로 엽니다.
- 토스페이먼츠 서버는 개발 샌드박스에서 닿지 않아 문서의 계약대로 구현하고 mock 모드로 검증했습니다. 실제 키와
  가격은 운영자가 `config.local.php`에서 넣습니다.
