시험은 개발용 사본에서 돌렸고, 저장소의 `server/` 폴더나 배포 폴더(`dist/`)에는 시험 파일을 만들지 않았어요.

## 2. 운영자가 먼저 할 일 (중요한 순서)

1. **HTTPS 인증서**를 설치하세요 (§2). 그러면 로그인과 결제가 암호화된 길로만 다녀요.
2. **관리자 센터 주소를 바꾸세요**: 설치 마법사의 "관리자 센터 주소를 아무도 모르는 이름으로 바꾸기"(기본으로 켜져 있어요), 또는 서버 컴퓨터에서 `php cli/tfm.php admin:path --random` (§6).
3. **2단계 인증**: 관리자 센터 → 🔐 2단계 인증 탭에서 휴대폰 인증 앱을 등록하고, 모든 관리자가 등록하면 `security.admin_2fa` 를 `required` 로 (§6).
4. **관리자 허용 주소**: `security.admin_ip_allowlist`(또는 환경 변수 `TFM_ADMIN_IPS`)에 관리자가 일하는 곳의 인터넷 주소를 적어요 (§6).
5. **DB 잠그기 점검표**를 한 번 따라 하세요: root 비밀번호, 익명 계정·test DB 지우기, phpMyAdmin 은 서버 컴퓨터에서만 (§1).
6. **토스페이먼츠 내 키**를 넣고, 웹훅 주소와 하루 한 번 `sub:renew` 예약을 등록하세요 (§15). 키가 없으면 결제는 "설정 필요"로 꺼져 있어요.
7. **웹 서버 설정 두 줄 + PHP 설정 두 줄**: httpd.conf 에 `ServerTokens Prod`·`ServerSignature Off`·`TraceEnable Off`, php.ini 에 `display_errors = Off`·`expose_php = Off` (§11, §16).
8. **데이터 폴더를 웹 루트 밖으로** 옮기면 가장 안전해요: 환경 변수 `TFM_DATA_DIR` (§19).
9. **백업**: DB 와 `data/secret.php` 를 **함께**, htdocs 밖에 보관하고 한 달에 한 번 되살려 보기 (§1).
10. **서버 프로그램 업그레이드 계획**: PHP 7.2·MariaDB 10.3 은 보안 업데이트가 끝났어요 (§17).
11. 이번 버전으로 올리기 **전부터 있던 로그 파일**(`data/logs/app-*.log.php`)은 지우세요: 예전 버전은 결제가 실패하면 결제 수단 키(빌링키)를 로그에 남겼을 수 있어요 (§1, §21).

언제든 **관리자 센터 → 🩺 시스템 점검** 또는 서버 컴퓨터에서 `php cli/tfm.php config:check` 를 열면 무엇이 남았는지 ✅ / ⚠️ / ⛔ 로 보여 줘요.

## 3. 항목별 보고

### §1. 데이터베이스를 안전하게 잠가 줘

**발견한 문제**
- 기본 설정이 **DB 최고 관리자(root) + 빈 비밀번호**였고(`config/config.php`), 설치 마법사도 입력한 root 정보를 그대로 `config/config.local.php` 에 적었어요. 체험관에 구멍이 하나만 생겨도 DB 전체(다른 DB 까지)를 지울 수 있는 열쇠가 쓰이는 상태였어요. (정적 검토 F13, 공격 시험 S01)
- `auto_migrate`(실행 중 표 구조를 바꾸는 기능)가 켜져 있어서 실행 계정에 표를 만들고 지우는 권한이 필요했어요.
- **결제 수단 키(빌링키)** — 카드를 계속 결제할 수 있는 값 — 가 DB 에 **평문**(그대로 읽히는 글자)으로 저장됐어요 (S01).
- 점검 화면에 "DB 를 어떤 계정으로 쓰고 있는지" 확인하는 줄이 없었어요 (S01).
- 결제가 실패하면 빌링키가 들어간 주소가 **로그 파일에 평문으로** 남았어요 (검토 F-B, `lib/Toss.php`).

**고친 내용**
- 설치 마법사(`install.php`)와 `php cli/tfm.php install` 이 **체험관 전용 DB 계정** `tfm_무작위8자` 를 만들어요: 비밀번호 32자 무작위, 이 데이터베이스 하나에 **읽기·쓰기·고치기·지우기(SELECT·INSERT·UPDATE·DELETE)만**. 표를 만들거나 지울 수 없고 다른 DB 도 못 봐요. 입력한 root 정보는 설치하는 동안 한 번만 쓰고 **어디에도 저장하지 않아요**. `auto_migrate` 는 꺼요.
- 업그레이드는 `php cli/tfm.php migrate --admin-user root` (그때만 잠깐 관리자 계정), 예전 설치를 전용 계정으로 바꾸기 `db:account --admin-user root`, 전용 계정 비밀번호 바꾸기 `db:rotate-password --admin-user root`. 비밀번호는 명령줄에 쓰지 않고 화면에 보이지 않게 물어봐요.
- DB 연결 옵션: 질의 흉내 기능 끔, 한 번에 여러 문장 실행 끔, 파일 읽어 넣기(LOAD DATA LOCAL) 끔, **다른 컴퓨터의 DB 는 암호화(TLS) 연결만**.
- SQLite: 추측할 수 없는 파일 이름(`db-무작위.sqlite`), 권한 0600(서버 계정만 읽기). **백업도 무작위 이름 + 0600** (이번에 0640 → 0600 으로 고쳤어요).
- 빌링키와 관리자 2단계 인증 비밀 키를 **AES-256-GCM 으로 봉인**(암호화)해서 저장해요. 열쇠(`data_key`)는 `data/secret.php` 에만 있어요. 예전 평문 값은 처음 쓸 때 봉인돼요.
- 결제 실패 로그에는 빌링키·결제 키 대신 "어떤 종류의 요청인지"만 남겨요.
- 점검 화면 "🗄️ DB 계정": 실행 계정이 root·빈 비밀번호·전체 권한이면 ⛔, 표를 바꾸는 권한이 있으면 ⚠, MariaDB 의 `test` DB 가 모두에게 열려 있으면 ⚠.
- 관련 커밋: c671306 · 181d753 · d768423 · 3389d58 · (이번) 백업 0600.

**테스트**
- 공격 시험 S01: "SQLite 파일 이름·0600", "빌링키가 봉인되어 저장됨", "MariaDB 최소 권한 계정으로 가입·로그인·저장·채팅", "점검 화면이 root/빈 비밀번호를 ⛔", "설치가 전용 계정을 만들고 관리자 정보는 저장하지 않음" — **5/5** (MariaDB 4/4 + SQLite 전용 1개).
- `tests/security-data-unit.php` (MariaDB): 전용 계정이 만들어지고 `config.local.php` 에 그것만 적힘 · 계정 권한이 정확히 네 가지 · CREATE/ALTER/DROP·`mysql.user` 읽기·다른 DB 사용 불가 · 다시 설치하면 비밀번호가 바뀌고 예전 것은 안 됨 · `db:account` 로 바꾸기(자료 유지) · 권한이 없으면 손으로 실행할 SQL 을 보여 줌 · 결제 실패 로그에 키가 없음 · **`cli backup` 사본이 무작위 이름 + 0600** (이번에 추가).

**운영자가 할 일** — "DB 잠그기 점검표" (서버 컴퓨터에서, phpMyAdmin 의 SQL 탭 또는 `C:\xampp\mysql\bin\mysql.exe -u root -p`)
1. **root 에 비밀번호 넣기**: `ALTER USER 'root'@'localhost' IDENTIFIED BY '20자-이상-긴-비밀번호';` (`127.0.0.1`, `::1` 도 같은 줄로) → `FLUSH PRIVILEGES;`. phpMyAdmin 은 `C:\xampp\phpMyAdmin\config.inc.php` 에서 `$cfg['Servers'][$i]['auth_type'] = 'cookie';` (비밀번호를 파일에 적지 않아요).
2. **익명 계정 지우기**: `DROP USER IF EXISTS ''@'localhost'; DROP USER IF EXISTS ''@'%'; FLUSH PRIVILEGES;`
3. **test 데이터베이스 지우기**: `DROP DATABASE IF EXISTS test; DELETE FROM mysql.db WHERE Db = 'test' OR Db = 'test\\_%'; FLUSH PRIVILEGES;`

5. **phpMyAdmin 은 서버 컴퓨터에서만**: `C:\xampp\apache\conf\extra\httpd-xampp.conf` 의 phpMyAdmin 부분이 `Require local` 인지 확인.
6. **전용 계정 확인**: `SHOW GRANTS FOR 'tfm_xxxxxxxx'@'localhost';` 에 `SELECT, INSERT, UPDATE, DELETE ON fermentation\_metaverse.*` 와 `USAGE` 두 줄만 있어야 해요. 예전 설치(root 로 도는 중)는 `php cli/tfm.php db:account --admin-user root` 한 번.

8. 이번 버전으로 올리기 전부터 있던 `data/logs/app-*.log.php` 는 지우세요 (예전 버전의 결제 실패 줄에 빌링키가 남았을 수 있어요).

### §2. HTTPS 를 강제로 쓰게 해 줘

**발견한 문제**
- 루트 `.htaccess` 의 "http → https 이동" 부분이 **주석(꺼진 상태)** 이었어요 (F17). 그래서 공개 주소로 `http://` 로 들어와도 그대로 응답했고, **로그인 비밀번호가 암호화 없이** 오갈 수 있었어요 (S02: GET 200, POST 처리됨).
- 요청이 HTTPS 인지 판단할 때 포트 번호 443 만 보고 믿었어요 — Apache 에서는 이 값이 방문자가 보낸 Host 에서 올 수 있어요 (F12).
- 점검 화면이 HTTPS 를 끈 공개 서버를 ⛔ 로 알리지 않았어요.

**고친 내용**
- 설정 `security.force_https` = `auto`(기본: 서버 컴퓨터 자신(localhost)이 아니면 강제) · `on` · `off`.
- 암호화 없는 **GET 요청 → 308 로 https 주소로 이동**, 그 밖의 요청(로그인 같은 POST) → **403 `HTTPS_REQUIRED`** — 비밀번호를 **읽기 전에** 거절해요.
- 루트 `.htaccess` 의 이동 규칙을 켰어요 (localhost 는 제외). 프록시가 보내는 `X-Forwarded-Proto` 는 `trusted_proxies` 에 적은 주소에서 온 것만 믿어요.
- HTTPS 응답에는 HSTS(브라우저에게 "앞으로 이 사이트는 https 로만" 이라고 알려 주는 머리글), 쿠키에는 `Secure`.
- 점검: HTTPS 강제를 끈 공개 서버는 ⛔.
- 관련 커밋: a9eb62a · dabd5af.

**테스트** — S02 **8/8**: force_https=on 이면 http GET → 308, http POST → 403 `HTTPS_REQUIRED` · 믿을 수 없는 곳의 전달 머리글은 https 로 치지 않음 · 믿는 프록시 뒤 HTTPS 에서 HSTS + Secure 쿠키 · 기본값 auto 에서 localhost 는 그대로, 공개 주소는 이동/거절 · 점검 ⛔ · Apache `.htaccess` 가 정적 파일까지 https 로 보냄.

**운영자가 할 일**
1. 인증서 설치: 도메인이 있으면 Let's Encrypt(Windows: win-acme), 없으면 `C:\xampp\apache\conf\extra\httpd-ssl.conf` 에 인증서 연결.
2. `force_https` 는 `auto` 그대로 두세요. 인증서 없는 교실 내부망에서만 `off` (점검 화면이 경고해요).
3. 리버스 프록시(앞에 다른 서버를 두는 경우) 뒤라면 그 프록시의 주소를 `security.trusted_proxies` 에 적으세요.

### §4. XSS(남이 심은 스크립트 실행) 공격을 막아 줘

**발견한 문제**
- 남이 심은 스크립트가 **실행되는** 구멍은 시작할 때부터 없었어요 (S04 10/10). 채팅·닉네임·메모는 이미 글자 그대로 보여 주고 있었어요.
- 다만 **글 위조**가 있었어요: 결제창에서 돌아오는 주소 `api/sub/return.php` 가 결제창의 `?message=` 를 그대로 체험관 주소(`?sub=fail&msg=…`)에 붙였고, 체험관이 그 글을 알림에 보여 줬어요. 누군가 링크를 만들어 보내면 체험관 이름으로 아무 문장이나 보일 수 있었어요 (F11, 검토 C1). `?sub=ok&tier=4` 는 결제 없이 "4배 빠르게!" 축하를 보여 줬어요.

**고친 내용**
- `return.php` 는 **정해진 낱말만** 넘겨요 (`sub`, `tier`, `code`, `why`) — 체험관이 그 낱말에 맞는 **고정 문장**을 보여 줘요. 결제창의 문장은 버려요. 축하는 **서버가 확인한 단계**로만 보여 줘요 (커밋 dff7f86).
- API 는 JSON 만, `nosniff`, `< > & ' "` 를 `\uXXXX` 로 바꿔 보내요. 관리자 센터는 **스크립트 0개** + 모든 값 `htmlspecialchars`, 설치 마법사도 모든 값을 바꿔 써요. 체험관은 해시 기반 CSP(허락한 스크립트만 실행).

**테스트** — S04 **12/12**: 닉네임에 스크립트·이벤트·SVG·`javascript:` 안 됨 · 채팅 글이 무해하게 돌아옴 · 신고 메모가 관리자 화면에서 글자로만 보임 · 관리자 화면·설치 마법사·`return.php` 의 모든 주소 값이 그대로 되비치지 않음 · `return.php` 가 정해진 낱말만 보냄 · CSP 검사 · 접속자 꾸미기 값은 허락된 값만 · 이번 시험의 모든 JSON 에 날것의 `< > & '` 없음 · 모든 PHP 응답에 CSP. 브라우저 시험 `node tests/sub-return-client.mjs` 23/23.

### §5. 수상한 활동을 기록하고 지켜봐 줘

**발견한 문제** — 보안 기록 표(`security_events`)와 차단 표(`ip_blocks`)는 있었지만 **아무도 쓰지 않았어요** (S05, 14개 구멍): 토큰 없는 요청, 다른 사이트에서 온 요청, SQL·스크립트·경로 공격 문자열, 로그인 잠금, 관리자 엿보기, 위험한 업로드, 치트 저장, 결제 금액 조작이 하나도 기록되지 않았고, 같은 주소에서 90번 공격해도 막히지 않았어요. `/.git/config` 같은 미끼 주소도 그대로 열렸어요.

**고친 내용**
- `Tfm\SecEvent::log(종류, 등급, 내용)` → 보안 기록 + 파일 로그. 종류: `csrf_fail`, `origin_mismatch`, `admin_denied`, `admin_ip_denied`, `admin_2fa_fail`, `login_locked`, `probe_sqli`, `probe_xss`, `probe_traversal`, `honeypot`, `payment_tamper`, `upload_rejected`, `save_rejected`, `https_required`, `ip_blocked`.
- `Tfm\Firewall::check()` 이 모든 입구에서 먼저 돌아요: 막힌 주소는 403 `IP_BLOCKED`.
- **자동 차단**: 한 주소에서 공격 같은 기록이 **600초에 25번** → **30분 차단**, 다시 걸리면 2배씩(최대 24시간). 서버 컴퓨터 자신과 `security.block.exempt`(예: 학교 주소)는 자동 차단하지 않아요.
- **함정(honeypot)**: 스캐너가 찾는 주소(`/.env`, `/wp-login.php`, `/phpmyadmin`, `/.git/config`, `*.bak` …)를 `api/trap.php` 로 보내 기록하고 빈 404 로 답해요.
- 다른 사이트가 방문자의 브라우저를 시켜 보낸 요청(`Sec-Fetch-Site: cross-site`)은 정보로만 기록해요 — 나쁜 페이지 하나가 교실 전체 주소를 막아 버리지 못하게요 (검토 F-A, 커밋 5c5afde).
- 한 주소의 기록은 1분에 120줄까지(기록 넘침 방지), 90일 보관. 기록에 들어가는 제어 문자는 `\u` 표시로 바꿔서 관리자 화면·명령 창을 망가뜨리지 못해요 (커밋 72d8cb6).
- 관리자 센터 **🛡️ 보안 탭**: 오늘의 수상한 활동 수, 종류·등급·기간 필터, 주소는 끝자리를 가리고 짧은 지문으로, "이 주소 1시간 차단", 막아 둔 주소와 차단 해제, 관리자 로그인 기록. 서버 컴퓨터에서 `php cli/tfm.php security:events`, `ip:block <주소> [초]`, `ip:unblock <주소>`.
- 알림 메일·웹훅은 설정 파일에서만 켤 수 있어요(기본 꺼짐, https 웹훅만).
- 관련 커밋: a9eb62a · dabd5af · 5c5afde · 72d8cb6.

**테스트** — S05 **16/16**: 위 10가지 공격이 각각 기록됨 · 함정이 404 + honeypot 기록 · 같은 주소의 반복 공격 → 403 `IP_BLOCKED`, 다른 주소는 정상 · 꾀어낸 방문자(교차 사이트)는 차단되지 않음 · 미끼 주소가 내장 서버와 Apache 에서 403/404 · 하위 폴더 설치에서도 함정 기록. 단위 시험: 기록 형식·등급·홍수 상한·90일 정리·차단 25번째·2배·24시간 상한·창 밖은 세지 않음·localhost 와 예외는 차단 안 함.

**운영자가 할 일**
1. 일주일에 한 번 🛡️ 보안 탭을 열어 보세요. 같은 주소가 계속 보이면 "이 주소 1시간 차단" 또는 `ip:block`.
2. 학교·교육장처럼 **여러 아이가 한 인터넷 주소**를 함께 쓰면 그 주소를 `security.block.exempt`(환경 변수 `TFM_BLOCK_EXEMPT`)에 적으세요.
3. 알림을 받고 싶으면 `config/config.local.php` 의 `security.alerts` 에 메일 또는 https 웹훅을 적어요(선택).

### §6. 관리자 페이지 경로를 잠가 줘

**발견한 문제**
- 관리자 화면이 누구나 짐작하는 주소 `admin.php` 에 있었고, 비밀번호 하나로만 들어갔어요(2단계 인증 없음, 허용 주소 없음) (S06, 8개 구멍).
- 관리자가 아직 없을 때 "서버 컴퓨터(localhost)에서 접속하면 첫 관리자로 지정" 하는 기능이 있었는데, 터널·포트 전달 프로그램 뒤에서는 **인터넷의 누구나 localhost 로 보여서** 남이 첫 관리자가 될 수 있었어요 (F4).
- 쿠키 없는 방문마다 세션 파일이 생겼고(F9), 로그인 화면에 버전이 보였어요(F15).
- 고치는 중에 검토로 더 찾은 것: 2단계 인증 코드를 하루 약 600번 시도할 수 있었어요(→ 고침 52878d3). 허용 주소 밖의 방문자도 관리자 화면의 모양 파일(admin.css)과 "폴더 끝 / 붙이기" 이동은 받아서, 관리자 폴더가 있다는 것을 알 수 있었어요(→ 고침 427e52b).
- 이번 마지막 점검에서 찾은 것: **설치 마법사가 무작위 폴더 이름을 제안하지 않아서**, 새로 설치한 서버는 운영자가 따로 바꿀 때까지 누구나 짐작하는 `/admin/` 에 있었어요 (→ 이번에 고침).

**고친 내용**
- 관리자 센터는 **자기 폴더** `admin/` (`index.php` + `.htaccess`)에 있고, 화면 모양은 `lib/admin.css`(웹에서 직접 안 열림)를 주소 확인 뒤에 보내요. 예전 `admin.php` 는 **없는 페이지(404)** 처럼 답하고 방문을 함정으로 기록해요.
- **폴더 이름은 자유**: `php cli/tfm.php admin:path --random` → `admin-무작위10글자`, 직접 정하기 `admin:path 이름`, 지금 이름 보기 `admin:path`. **설치 마법사가 무작위 이름을 제안**해요(기본으로 켜짐) — 새 주소는 설치 완료 화면에만 한 번 보이고, 공개된 설치 화면에는 나오지 않아요. 관리자 계정으로 체험관에 로그인하면 메뉴의 관리자 센터 버튼이 알아서 새 주소로 가요(`api/auth/me.php` 가 **관리자에게만** 주소를 알려 줘요).
- **허용 주소**(`security.admin_ip_allowlist` / `TFM_ADMIN_IPS`, IPv4·IPv6·범위): 다른 주소에는 **없는 페이지와 똑같은 404** + `admin_ip_denied` 기록 — 화면, 모양 파일, 끝에 `/` 없는 폴더 주소까지.

### §9. 요청 횟수 제한을 걸어 줘

**발견한 문제**
- 몇몇 엔드포인트는 한도가 없거나 다른 것과 함께 썼어요 (S09: `admin/health` 가 `admin/stats` 의 한도를 함께 쓰는데도 200, 업로드 21번에 429 없음 …).
- 고정된 시간 칸의 경계에서 한도보다 1번 더 통과했어요 (커밋 d7579eb 에서 고침).
- 검토로 찾은 것: 여러 주소에서 한 계정의 비밀번호를 틀리면 **주인이 맞는 비밀번호로도 못 들어갔어요** — 닉네임은 공개라 누구나 남의 계정(관리자 포함)을 잠글 수 있었어요(F-B). 매번 다른 가짜 세션 쿠키를 보내면 요청마다 새 세션 파일·새 한도 칸이 생겼어요(F9·F-D).

**고친 내용**
- **모든 엔드포인트에 이름 붙은 한도** (`config.php` 의 `rate_limits`, 부록 A 에 표): 로그인한 사람은 계정별, 아니면 세션별 + 주소 전체 상한(×25), 로그인은 주소별, 가입은 세션별 + 주소별(`register_ip`), 결제 쓰기는 계정별, 함정·설치·결제창 복귀·웹훅은 주소별.
- 미끄러지는 시간 창(앞 칸의 몫을 올림으로 셈) → 한도 + 1 은 언제나 걸려요.
- 넘으면 **429 + `Retry-After`** + `data.retryAfter`(몇 초 뒤에 다시).
- 계정 잠금은 "여러 주소에서 온 실패"로만 세고, **깨끗한 주소에서 맞는 비밀번호는 통과**해요 (커밋 0e4aa8a).
- 처음 보는 세션 쿠키는 다시 이어 쓰기만 하는 요청에서 **새 세션 파일을 만들지 않아요** (커밋 3a831f4).

**테스트** — S09 **9/9**: 한 계정 6번째 비밀번호 → 429 · 한 주소에서 여러 계정 → 61번 안에 429 · **여러 주소의 공격 뒤에도 주인은 맞는 비밀번호로 로그인** · 가입 21번 안에 429 · 저장 1분 46번 안에 · 채팅 1초에 2번째 거절 · 신고 1시간 11번 안에 · 가짜 쿠키를 돌려도 세션 파일이 쌓이지 않음 · 그 밖의 모든 엔드포인트가 정해진 한도 안에서 429 + `Retry-After`.

**운영자가 할 일** — 평소에는 없어요. 한 교실이 한 인터넷 주소로 많이 들어와서 "요청이 너무 많아요" 가 자주 보이면 `rate_limits`, `login.ip_max_failures`, `security.rate_limit_ip_multiplier` 를 늘리거나 그 주소를 `security.block.exempt` 에.

### §10. CORS 설정을 필요한 곳만 허용하게 좁혀 줘

**발견한 문제** — 기본값은 이미 "같은 사이트만"(CORS 머리글 없음)이었어요. 다만 꼭 필요한 공개 정보만 다른 사이트에 열어 주는 **허용 목록 기능이 없었어요** (S10, 3개).

**고친 내용** — `security.cors_allowed_origins` (`TFM_CORS_ORIGINS`): 정확한 `https://호스트[:포트]` 만, `*` 는 절대 안 돼요. 그 주소에만, **읽기 전용 공개 GET 4개**(`ping`, `time`, `ranking/top`, `sub/status`)에서 `Access-Control-Allow-Origin: <그 주소>` + `Vary: Origin`. 로그인 정보(쿠키)는 같이 보내지 않고, 쓰기 요청과 그 밖의 사전 요청(preflight)은 403. 점검 화면은 `*` 를 ⛔ 로 알려요. (커밋 a9eb62a)

**테스트** — S10 **4/4**: 기본은 어떤 엔드포인트에도 CORS 머리글 없음 · 목록의 주소만 정확히 되돌려 줌 · 비슷한 주소·다른 포트·`null` 은 안 됨, `*` 없음 · 로그인 정보·POST·비공개 GET·사전 요청은 언제나 안 됨.

**운영자가 할 일** — 없어요. 다른 사이트(예: 학교 홈페이지)가 랭킹을 보여 줘야 할 때만 그 주소를 적으세요.

### §11. 보안 헤더를 추가해 줘

**발견한 문제** (S11, 6개): 직접 열면 안 되는 PHP 파일의 404 에 `X-Powered-By: PHP/8.3.6`(PHP 버전) · `index.html` 에 CORP 없음 · css·js 에 CSP·CORP 없음 · Apache 오류 페이지에 `nosniff`·CSP 없고 서버 서명(버전) 표시 · 모든 응답의 `Server: Apache/2.4.58 (Ubuntu)` · TRACE(요청을 그대로 되돌려 주는 방식)에 200.

**고친 내용**
- 응답 종류(API · 관리자 · 설치 · 정적 파일 · 오류 페이지)마다 **머리글 한 벌**: CSP, `X-Content-Type-Options: nosniff`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, COOP, CORP, 동적 응답 `Cache-Control: no-store`, https 면 HSTS.
- 모든 "직접 열기 막기" 404 에서 `X-Powered-By` 를 지워요. 정적 파일은 `.htaccess` 의 확장자별 규칙으로, 오류 페이지는 자체 `e403.html`/`e404.html`(하위 폴더 설치도)로.
- `Server` 버전과 TRACE 는 **`.htaccess` 로 바꿀 수 없는 Apache 전체 설정**이에요 → 점검 화면 "웹 서버 설정(ServerTokens · TraceEnable)" 이 운영자에게 알려요. (커밋 a9eb62a · dabd5af · 59882f6 · 690d1b9)

**테스트** — S11 **12/12**: API 정상·오류 응답 · 관리자 로그인과 모든 탭 · 설치(열림·잠김) · 비공개 PHP 404 에 본문·`X-Powered-By` 없음 · Apache: `index.html`, css·js, 업로드 사진(sandbox CSP), mod_php 뒤의 모든 입구, 403/404 오류 페이지, 진짜 하위 폴더 설치의 404 · 서버 버전/TRACE 는 숨겨지거나 점검 화면이 알림.

**운영자가 할 일** — `C:\xampp\apache\conf\httpd.conf` 맨 아래에 다음 세 줄을 넣고 Apache Stop → Start:
```apache
ServerTokens Prod
ServerSignature Off
TraceEnable Off
```
그리고 `C:\xampp\php\php.ini` 에서 `expose_php = Off`.

### §12. 세션 쿠키를 안전하게 설정해 줘

**발견한 문제** — 세션 쿠키는 시작할 때부터 대부분 안전했어요(HttpOnly · SameSite=Lax · 설치 폴더 경로 · 엄격 모드 · 쿠키로만, S12 10/11). 빠진 것은 **관리자 승격 쿠키(SameSite=Strict)** — 관리자 센터 자체가 따로 없었기 때문이에요. 또 가짜 쿠키를 보내면 새 세션 파일이 생겼어요(§9).

**고친 내용** — 세션 쿠키 `TFMSESSID`: HttpOnly(스크립트가 못 읽음), SameSite=Lax(다른 사이트에서 몰래 못 씀), https 면 Secure, 경로 = 설치 폴더, 엄격 모드, 주소창 세션 번호 금지, **로그인·권한 변경·2단계 인증 때 세션 번호 교체**, 2시간 유휴·24시간 최대, 브라우저 지문(User-Agent)이 바뀌면 끝. 관리자 승격 쿠키 `TFMADM`: SameSite=**Strict** · HttpOnly · 관리자 폴더에만. (커밋 31fe702 · 3a831f4)

**테스트** — S12 **11/11**: 쿠키 속성 · 하위 폴더 경로(내장 서버·Apache) · 가입·로그인·로그아웃마다 번호 교체, 예전 번호는 죽음 · 고정 공격(미리 심은 번호) 안 됨 · 주소·본문의 번호 무시 · 2시간(시험은 2초) 유휴 · 최대 수명(시험 3초) · 다른 브라우저의 훔친 쿠키는 로그인 아님 · 권한 변경 → 열려 있던 세션 끝 · 승격 쿠키 Strict + HttpOnly + 폴더 경로.

**운영자가 할 일** — HTTPS 를 켜면(§2) `Secure` 가 저절로 붙어요. 그 밖에는 없어요.

### §13. CSRF 보호를 넣어 줘

**발견한 문제** — 상태를 바꾸는 요청은 시작할 때부터 세션 토큰 + 출처(`Origin`/`Sec-Fetch-Site`) 검사가 있었어요(S13 12/12). 새 관리자 센터의 모든 작업도 같은 보호가 필요했고, 출처 머리글이 없거나 `null` 일 때를 어떻게 다룰지 정해야 했어요(F16).

**고친 내용** — 모든 POST: 세션별 32바이트 토큰(`X-CSRF-Token` 머리글) + 다른 사이트의 `Origin` 이나 `Sec-Fetch-Site: cross-site` 는 토큰이 맞아도 403 + `origin_mismatch` 기록. 출처가 없거나 `null` 이면 토큰이 반드시 맞아야 해요. https 요청에 http 출처는 다른 사이트로 봐요. 관리자 센터의 모든 폼(22개 작업)도 토큰 + 같은 사이트 확인 + 303. 세션이 없는 관리자 로그인 폼은 서버에 아무것도 남기지 않는 서명 토큰을 써요(F9). 토큰은 로그인·로그아웃 때 바뀌어요. (커밋 a9eb62a · 31fe702)

**테스트** — S13 **12/12**: 모든 POST 가 토큰 없음·틀린 토큰·다른 세션의 토큰·다른 사이트 출처·`Sec-Fetch-Site: cross-site` 를 403 · 비슷한 출처(다른 포트·뒤에 붙인 이름)도 다른 사이트 · 세션 없는 POST 는 401/403 · 토큰은 머리글로만(저장 비콘만 예외) · 정상 요청은 통과, 상태를 바꾸는 GET 은 405 · 웹훅(문서화된 예외)은 누구 대신 아무것도 못 함 · 관리자 폼 전부 · 로그인·로그아웃 때 토큰 교체.

**운영자가 할 일** — 없어요.

### §14. 파일 업로드 종류와 크기를 제한해 줘

**발견한 문제** — 사진 업로드 검사는 이미 튼튼했어요(S14 14/15). 남은 것: 파일을 받지 않는 엔드포인트에 `multipart/form-data` 를 보내면 415 로만 답하고 기록이 없었어요(S14) · PHP 의 그림 기능(GD)이 없으면 **원본을 그대로 저장**해서 사진 속 위치 정보(GPS)가 남을 수 있었어요(F8) · 웹 서버 쪽 업로드 크기 제한이 없었어요(F17).

**고친 내용** — 파일은 `journal/upload.php` 만 받아요. 다른 곳에 파일을 보내면 **400 `UPLOAD_NOT_ALLOWED`** + `upload_rejected` 기록. 사진: 로그인한 사람만, **5 MB 이하**, 내용으로 확인한 종류(finfo)가 **PNG·JPEG·WEBP** 이고 그림 정보(getimagesize)와 일치, 해상도·전체 화소 상한(압축 폭탄 방지), 스크립트·HTML 이 섞인 파일 거부, **GD 로 다시 그려 저장**(위치 정보·숨긴 데이터 제거), 무작위 128비트 이름 + 강제 확장자, 하루·전체 개수 제한. **GD 가 없으면 업로드를 받지 않아요.** `.user.ini` 와 `.htaccess`: `upload_max_filesize 6M`, `post_max_size 8M`, `max_file_uploads 2`. `uploads/.htaccess`: 스크립트 실행 금지, `[a-f0-9]{32}.(png|jpg|webp)` 이름만, sandbox CSP. (커밋 a9eb62a · dabd5af · 690d1b9)

**테스트** — S14 **15/15**: GIF·SVG(스크립트)·PDF·PHP·HTML 섞인 PNG·PHP 섞인 PNG·5 MB 초과·30000×30000 주장·5000×5000 화소 폭탄·빈 파일·글 파일·두 번째 파일 칸 → 모두 거절 · 이중 확장자·경로·NUL 이름은 디스크에 안 닿음 · 정상 PNG 는 다시 그려져 바이트가 달라짐 · 로그인 없이 안 됨 · 다른 엔드포인트의 multipart → 400 · Apache: uploads 안에서 실행 안 됨, 정해진 이름만 · 웹 서버를 거친 큰 업로드도 거절.

**운영자가 할 일** — `C:\xampp\php\php.ini` 에서 `extension=gd`(XAMPP 7.2 는 `extension=gd2`) 앞의 `;` 를 지우고 Apache 재시작. 점검 화면의 "PHP 확장: gd" 가 ✅ 인지 확인.

### §15. 가격과 결제 금액을 서버에서 확인해 줘

**발견한 문제**
- 결제 승인에서 금액을 글자 `"2900"` 으로 보내도 받아들였어요(S15).
- 토스 응답에 결제 금액(`totalAmount`)이 없으면 "같다"고 봤고, 통화·주문 번호·결제 키를 비교하지 않았어요(F10). 같은 주문을 두 번 동시에 승인하면 이미 결제된 주문이 "실패"로 바뀌거나, 돈은 나갔는데 단계가 안 오를 수 있었어요(F5·F6).
- 검토로 찾은 것(모두 고침):
  - (높음) 자동 갱신이 켜진 사람이 다른 단계를 1개월 결제하거나 관리자가 무료로 높은 단계를 주면, **다음 자동 갱신이 등록하지 않은 높은 가격으로 매달 청구**됐어요(F-A, 커밋 c245c7e).
  - 관리자 센터 "지금 갱신 시도" 를 **누를 때마다 다시 청구**됐어요(F-C, 커밋 3b47a73).
  - MariaDB 에서 한 계정의 두 결제를 동시에 승인하면 **두 번 결제됐는데 한 기간만** 더해졌어요(F-D, 커밋 05da87a).

**고친 내용**
- 주문 금액은 **서버의 단계 표**로 만들고(브라우저가 보낸 가격은 무시), 승인 금액은 **JSON 정수 1~10,000,000** 이고 주문 금액과 정확히 같아야 해요. 다른 계정의 주문·이미 처리된 주문은 거절.
- 토스 응답은 상태 DONE + `totalAmount`(있고, 정수, = 주문 금액) + 같은 주문 번호 + KRW + 같은 결제 키여야 해요. 아니면 주문 실패 + `payment_tamper` 기록 + **결제 자동 취소**.
- 주문을 한 번에 하나만 처리(행 잠금 + 선점 표시), 응답이 늦으면 503 `PAYMENT_PENDING` 으로 기다렸다가 다시 조회. 웹훅은 본문을 믿지 않고 토스에 다시 묻고, **단계를 올리지 못해요**.
- 자동 갱신은 **카드를 등록한 그 단계만** 청구해요. 자동 갱신이 켜진 동안 다른 단계 결제·부여는 409 `SUB_AUTO_RENEW_ON`. 강제 갱신은 **한 기간에 한 번만**. 결제를 기록할 때 계정 줄을 먼저 잠가요.
- 관련 커밋: 181d753 · 05da87a · c245c7e · 3b47a73.

**테스트** — S15 **9/9**: 준비 금액은 서버 표에서 · 조작한 금액(낮게·0·음수·높게) 거절, 정확한 금액은 통과 · 금액은 정수만(소수·지수·글자·배열 거절) · 다른 계정의 주문 거절 · 다시 보낸 승인 거절(기간 안 늘어남) · 2~4 밖의 단계 거절 · 토스가 발급하지 않은 결제 키 실패, 금액을 바꾼 복귀 주소 실패 · 위조 웹훅은 단계를 못 올림 · 저장 데이터 속 가짜 구독은 서버 값으로 바뀜. `tests/security-data-unit.php` 의 결제 시험(자동 갱신 단계 5개, 강제 갱신 1번만, 두 결제 동시 승인 2개 — MariaDB 포함), `tests/server-e2e.mjs` 의 구독 흐름.

**운영자가 할 일**
1. §8 처럼 **내 토스 키**를 넣고, 실제 판매 전에 `test_` 키로 **한 번 결제해 보세요**(토스 서버는 개발 환경에서 닿지 않아 모의 모드와 공개 API 설명서로 시험했어요).
2. 토스 개발자센터 웹훅 주소: `https://<내 도메인>/<설치 폴더>/api/sub/webhook.php`.
3. Windows 작업 스케줄러에 하루 한 번 `C:\xampp\php\php.exe C:\xampp\htdocs\metaverse\cli\tfm.php sub:renew`.

### §16. 실서비스에서는 디버그 모드를 꺼 줘

**발견한 문제**
- (가장 위험했던 것) **설치 마법사 `install.php` 가 이미 쓰고 있는 서버에서도 열려 있어서**, 인터넷의 방문자가 설치를 다시 돌려 **스스로 관리자가 될 수 있었어요**(F1, S16 — 시험에서 실제로 성공). 잠긴 뒤에도 403 화면이 잠금 푸는 방법을 알려 줬어요.
- 공개 운영 서버에서도 모의 결제가 켜져 있으면 결제 없이 4배 단계를 받을 수 있었고, 점검 화면은 ⚠ 로만 알렸어요(S16).
- 설치 마법사의 오류 응답에 PHP 버전이 보였어요(S16).

**고친 내용**
- `install.php` 는 잠금 파일이 있거나, `config.local.php` 가 있거나, DB 에 계정이 하나라도 있으면 **없는 페이지(404)** 처럼 답해요. 열려 있을 때도 모든 설치 요청에 **서버 컴퓨터에서만 볼 수 있는 일회용 설치 코드**가 필요해요(`php cli/tfm.php setup-code`, 또는 `data/setup-code.php` 를 메모장으로, 24시간). 화면에는 PHP 버전도 경로도 없어요.

**테스트** — S16 **11/11** (MariaDB 10/10 + SQLite 전용 1개): 깨진 JSON·잘못된 형식·빠진 칸·모르는 방식·나쁜 쿠키·나쁜 값의 오류 응답에 흔적 없음 · DB 를 망가뜨린 진짜 서버 오류 → 일반 500 + 참조 번호 · 잠긴 `install.php` → GET·POST 404 · **이미 쓰는 서버에서 원격 방문자는 설치 불가** · phpinfo·시험 스크립트 없음 · 공개 운영 서버의 모의 결제 거절 · 점검 ⛔ · 기본 production · 소스 맵 없음 · 이번 시험의 모든 응답에 스택·경로·버전·`X-Powered-By` 없음. `tests/security-data-unit.php`: 설치 코드 없이/틀리게 → 403 + 아무것도 안 씀, 코드로 설치 → 코드 사용 끝 → 404, 계정만 있어도 404.

### §21. 유출된 키는 폐기하고 새로 바꿔 줘

**고친 내용**

**테스트** — `tests/security-data-unit.php`: 데이터 키 교체 뒤 봉인 값이 같은 내용으로 열림, 예전 키 지워짐 · 앱 키 교체 뒤 세션 끝 · 실패하면 되돌림 · (MariaDB) DB 비밀번호 교체 뒤 예전 비밀번호로 접속 안 됨, 권한은 그대로.

**운영자가 할 일** (키가 새어 나갔다고 의심될 때)

## 부록 C. 실제 운영 환경(PHP 7.2.10 · MariaDB 10.3.8 · Apache 2.4.34 Win32)에서 확인하는 방법

개발 환경에는 PHP 7.2·MariaDB 10.3·Windows Apache 가 없어서 그 위에서는 시험을 돌리지 못했어요(문법은 `tools/php-compat.sh` 로 7.2 기준 0 오류). 그래서 설치한 뒤 **운영 서버에서 직접** 이렇게 확인해 주세요. 15분쯤 걸려요.

1. **서버 점검**: 명령 프롬프트에서 `C:\xampp\php\php.exe C:\xampp\htdocs\metaverse\cli\tfm.php status` → "종합" 에 ⛔ 가 없어야 해요. 이어서 `… cli\tfm.php config:check` (종료 코드 0).
2. **설치 마법사**: `http://localhost/metaverse/install.php` → 설치 코드(`… cli\tfm.php setup-code`)로 설치 → 완료 화면에 새 관리자 주소와 "🛡️ 설치 후 보안 점검" 표가 보여요. 설치 뒤 같은 주소를 다시 열면 **"Not Found"(404)** 여야 해요.
3. **관리자 센터**: 완료 화면의 새 주소로 로그인 → 🔐 2단계 인증 등록 → 로그아웃 → 다시 로그인할 때 6자리 숫자를 물어보면 성공. 예전 주소 `http://localhost/metaverse/admin.php` 와 `…/admin/` 는 404 여야 해요(이름을 바꿨다면).
4. **🩺 시스템 점검** 탭: "PHP 7.2" ⚠(업그레이드 권고)는 정상이에요. "웹 노출"·"DB 실행 계정"·"관리자 페이지 잠금" 줄에 ⛔ 가 없어야 해요.
5. **체험관**: `http://localhost/metaverse/` 에서 회원가입 → 저장 → 채팅 한 줄 → 로그아웃 → 다시 로그인했을 때 진행이 그대로면 성공.
6. **HTTPS**: 인증서를 단 뒤 `http://내도메인/metaverse/` 로 열면 `https://` 로 바뀌어야 해요.
7. **세션 쿠키 (PHP 7.2 만의 길)**: PHP 7.2 는 쿠키의 SameSite 를 다른 방법(경로 뒤에 덧붙이기)으로 넣어요. 브라우저 개발자 도구(F12) → Application → Cookies 에서 `TFMSESSID` 가 **HttpOnly · SameSite=Lax**, 관리자 센터의 `TFMADM` 이 **SameSite=Strict** 인지 봐 주세요. 이 길은 개발 환경(PHP 8.3)에서 실행되지 않았어요.
8. 이상한 점이 있으면 화면의 오류 번호(`rid`)로 `data/logs/app-날짜.log.php` 를 찾아 개발자에게 보내 주세요(로그에는 비밀 값이 없어요).

## 용어 풀이

| 말 | 뜻 |
|---|---|
| 서버 / 서버 컴퓨터 | 체험관 파일과 데이터베이스가 있는 컴퓨터(XAMPP 를 켠 PC). "서버 컴퓨터에서" = 그 PC 의 명령 프롬프트에서 |
| 데이터베이스(DB) | 회원·저장·채팅·결제 기록을 담는 창고. MariaDB(MySQL) 또는 파일 하나짜리 SQLite |
| root | DB 의 최고 관리자 계정. 모든 DB 를 지울 수 있어서 체험관이 평소에 쓰면 안 돼요 |
| 전용 계정 · 최소 권한 | 체험관만 쓰는 DB 계정. 꼭 필요한 일(읽기·쓰기·고치기·지우기)만 할 수 있게 한 것 |
| 평문 / 봉인(암호화) | 평문 = 누구나 읽을 수 있는 그대로의 글자. 봉인 = 열쇠 없이는 못 읽게 바꾼 것(AES-256-GCM) |
| 해시 | 원래 값으로 되돌릴 수 없게 한 방향으로만 바꾼 값. 비밀번호·백업 코드는 해시로만 저장 |
| HTTPS · 인증서 | 브라우저와 서버 사이를 암호화하는 길. 인증서는 그 길을 여는 신분증 |
| HSTS | "이 사이트는 앞으로 https 로만 열어" 라고 브라우저에게 기억시키는 머리글 |
| 머리글(헤더) | 응답과 함께 보내는 짧은 안내 줄. 브라우저가 보안 규칙으로 따라요 |
| CSP | "이 페이지에서는 허락한 스크립트만 실행해" 라는 머리글. XSS 를 막는 두 번째 벽 |
| XSS | 남이 심은 스크립트가 다른 사람 화면에서 실행되는 공격 |
| CSRF | 다른 사이트가 내 로그인 상태를 몰래 써서 요청을 보내는 공격. 토큰으로 막아요 |
| CSRF 토큰 | 이 체험관 화면만 아는 일회성 확인 값. 다른 사이트는 모르니까 가짜 요청을 구별해요 |
| SQL 인젝션 | 입력 칸에 DB 명령을 섞어 넣는 공격. 값을 따로 넘기는 방식(prepared statement)으로 막아요 |
| CORS | 다른 사이트의 스크립트가 우리 서버의 답을 읽어도 되는지 정하는 규칙 |
| 세션 · 쿠키 | 세션 = 서버가 기억하는 "지금 로그인한 사람", 쿠키 = 브라우저가 그 번호를 들고 다니는 작은 표 |
| HttpOnly · SameSite · Secure | 쿠키의 안전 표시: 스크립트가 못 읽음 · 다른 사이트에서 못 씀(Strict 는 더 엄격) · https 로만 |
| 2단계 인증(TOTP) | 비밀번호 + 휴대폰 인증 앱의 30초마다 바뀌는 6자리 숫자 |
| 백업 코드 | 휴대폰을 잃었을 때 한 번씩 쓰는 비상 코드 10개 |
| 승격 | 관리자 센터에 다시 로그인해서 관리자 일을 할 수 있게 된 상태(30분 동안 안 쓰면 끝) |
| 허용 주소 목록(allow-list) | 이 인터넷 주소에서만 열리게 하는 목록. 다른 곳에는 "없는 페이지" |
| IP 주소 · CIDR | 인터넷 주소(예: 203.0.113.7). `192.168.0.0/24` 처럼 쓰면 그 범위 전체 |
| 요청 한도(rate limit) · 429 | 짧은 시간에 너무 많이 보내면 잠깐 멈추게 하는 규칙. 429 = "잠시 뒤에 다시", `Retry-After` = 몇 초 뒤 |
| 함정(honeypot) | 공격 프로그램만 찾는 가짜 주소. 들어오면 기록하고 빈 404 |
| 자동 차단 | 같은 주소에서 공격이 일정 횟수 넘으면 그 주소를 잠깐 막는 것 |
| 감사 로그 | 누가 언제 무엇을 했는지 남기는 장부 |
| `.htaccess` | 폴더마다 두는 Apache 설정 파일. 비공개 폴더를 막고 머리글을 붙여요 |
| httpd.conf · php.ini | Apache 전체 설정 파일 · PHP 전체 설정 파일 (XAMPP: `C:\xampp\apache\conf\httpd.conf`, `C:\xampp\php\php.ini`) |
| 환경 변수 | 프로그램에 바깥에서 건네는 설정 값(예: `TFM_DATA_DIR`). Apache 에서는 `SetEnv` |
| 웹 루트 | 브라우저로 열 수 있는 폴더(XAMPP 의 htdocs). 비밀 파일은 그 밖이 가장 안전 |
| 404 · 403 · 308 | 없는 페이지 · 들어갈 수 없음 · 다른 주소로 영구 이동 |
| 엔드포인트 | 체험관이 서버에 말을 거는 주소 하나(예: `api/auth/login.php`) |
| 빌링키 | 카드를 다시 결제할 수 있게 토스가 주는 값(자동 갱신용) |
| 웹훅 | 토스 서버가 결제 취소 같은 일을 우리 서버에 알려 주는 주소 |
| 모의 결제(mock) | 진짜 결제 서버 없이 흐름만 시험하는 모드. 운영 서버에서는 꺼야 해요 |
| 설치 코드 | 서버 컴퓨터에서만 볼 수 있는 일회용 12자리 코드. "이 서버의 주인" 이라는 증거 |
| npm audit | 쓰는 프로그램 조각(패키지)에 알려진 취약점이 있는지 검사하는 명령 |
| 깃(git) 기록 | 코드가 바뀐 모든 순간을 저장한 기록. 한 번 들어간 비밀은 기록에 남아요 |
