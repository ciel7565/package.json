### §1. 데이터베이스를 안전하게 잠가 줘

**발견한 문제**
- 기본 설정이 **DB 최고 관리자(root) + 빈 비밀번호**였어요(`config/config.php:57-58`, `lib/Db.php:88`). 설치 마법사도 입력한 root 정보를 그대로 `config/config.local.php` 에 적었어요. → 체험관에 구멍이 하나만 생겨도, 공격자는 그 열쇠로 **이 DB 는 물론 같은 서버의 다른 DB 까지** 읽고 지울 수 있었어요. (정적 검토 F13, 공격 시험 S01)
- `auto_migrate`(실행 중에 표 구조를 바꾸는 기능)가 켜져 있어서 실행 계정에 표를 만들고 지우는 권한이 필요했어요.
- **결제 수단 키(빌링키)** — 카드를 다시 결제할 수 있는 값 — 가 DB 에 **평문**(누구나 읽을 수 있는 그대로의 글자)으로 저장됐어요. → DB 사본(백업 파일 하나)만 빼내도 그 카드로 결제를 일으킬 수 있었어요. (S01)
- 점검 화면에 "DB 를 어떤 계정으로 쓰고 있는지" 확인하는 줄이 없었어요 (S01).
- 결제가 실패하면 빌링키가 들어간 요청 주소가 **로그 파일에 평문으로** 남았어요(`lib/Toss.php:216`, `:297·:302·:308` — 3장 3.3 의 10번). → 로그 파일이나 그 백업을 본 사람은 빌링키를 얻을 수 있었어요.

**고친 내용**
- 설치 마법사(`install.php`)와 `php cli/tfm.php install` 이 **체험관 전용 DB 계정** `tfm_무작위8자` 를 만들어요: 비밀번호 32자 무작위, 이 데이터베이스 하나에 **읽기·쓰기·고치기·지우기(SELECT·INSERT·UPDATE·DELETE)만**. 표를 만들거나 지울 수 없고 다른 DB 도 못 봐요. 입력한 root 정보는 설치하는 동안 한 번만 쓰고 **어디에도 저장하지 않아요**. `auto_migrate` 는 꺼요.
- 업그레이드는 `php cli/tfm.php migrate --admin-user root`(그때만 잠깐 관리자 계정), 예전 설치를 전용 계정으로 바꾸기 `db:account --admin-user root`, 전용 계정 비밀번호 바꾸기 `db:rotate-password --admin-user root`. 비밀번호는 명령줄에 쓰지 않고, 화면에 보이지 않게 물어봐요.
- DB 연결 옵션: 질의 흉내 기능 끔, 한 번에 여러 문장 실행 끔, 파일 읽어 넣기(LOAD DATA LOCAL) 끔, **다른 컴퓨터의 DB 는 암호화(TLS) 연결만**.
- SQLite: 추측할 수 없는 파일 이름(`db-무작위24자.sqlite`), 권한 0600(서버 계정만 읽기 — 리눅스·맥에서). **백업도 무작위 이름 + 0600**(`cli backup`, 0640 이던 것을 마지막 점검에서 고침).
- 빌링키와 관리자 2단계 인증 비밀 키를 **AES-256-GCM 으로 봉인**(열쇠 없이는 못 읽게 암호화)해서 저장해요(`enc:v1:…`). 열쇠(`data_key`)는 `data/secret.php` 에만 있어요. 예전 평문 값은 처음 쓸 때 봉인돼요.
- 결제 실패 로그에는 빌링키·결제 키 대신 "어떤 종류의 요청인지" 만 남겨요.
- 점검 화면 "🗄️ DB 계정": 실행 계정이 root · 빈 비밀번호 · 전체 권한이면 ⛔, 표를 바꾸는 권한이 있으면 ⚠, MariaDB 의 `test` DB 가 모두에게 열려 있으면 ⚠.

### §2. HTTPS 를 강제로 쓰게 해 줘

**발견한 문제**
- 루트 `.htaccess` 의 "http → https 이동" 부분이 **주석(꺼진 상태)** 이었어요(F17). 그래서 공개 주소로 `http://` 로 들어와도 그대로 응답했고, 로그인 비밀번호가 암호화 없이 오갔어요(S02: http GET 200, http POST 처리됨). → 같은 와이파이·같은 학교망에 있는 사람이 비밀번호와 세션 쿠키를 엿볼 수 있었어요.
- 요청이 HTTPS 인지 판단할 때 포트 번호 443 만 보고 믿었어요(`lib/Core.php:324-333`, F12) — Apache 기본 설정에서는 이 값이 방문자가 보낸 `Host` 머리글에서 올 수 있어요.
- 점검 화면이 HTTPS 를 끈 공개 서버를 ⛔ 로 알리지 않았어요.

**고친 내용**
- 설정 `security.force_https` = `auto`(기본: 서버 컴퓨터 자신(localhost)이 아니면 강제) · `on` · `off`.
- 암호화 없는 **GET 요청 → 308 로 https 주소로 이동**, 그 밖의 요청(로그인 같은 POST) → **403 `HTTPS_REQUIRED`** — 비밀번호를 **읽기 전에** 거절해요.
- 루트 `.htaccess` 의 이동 규칙을 켰어요(localhost 는 제외, 정적 파일도). 프록시가 보내는 `X-Forwarded-Proto` 는 `security.trusted_proxies` 에 적은 주소에서 온 것만 믿어요.
- HTTPS 응답에는 HSTS(브라우저에게 "앞으로 이 사이트는 https 로만" 이라고 기억시키는 머리글), 쿠키에는 `Secure`.
- 점검: HTTPS 강제를 끈 공개 서버는 ⛔.
- 관련 커밋: a9eb62a · dabd5af.

**테스트** — S02 **8/8** (`node tests/security-e2e.mjs --apache --only S02`): force_https=on 이면 http GET → 308, http POST → 403 `HTTPS_REQUIRED`(비밀번호를 읽기 전) · 믿을 수 없는 곳의 전달 머리글은 https 로 치지 않음 · 믿는 프록시 뒤 HTTPS 에서 HSTS + Secure 쿠키 · 기본값 auto 에서 localhost 는 그대로, 공개 주소는 이동/거절 · 점검 ⛔ · Apache `.htaccess` 가 정적 파일까지 https 로 보냄.

**운영자가 할 일**
1. 인증서 설치: 도메인이 있으면 Let's Encrypt(Windows: win-acme), 없으면 `C:\xampp\apache\conf\extra\httpd-ssl.conf` 에 인증서 연결 — 순서는 `docs/SERVER-INSTALL-KO.md` 6장. **인증서 없이 공개 주소로 열면** 방문자가 열리지 않는 https 주소로 보내져요.
2. `force_https` 는 `auto` 그대로 두세요. 인증서 없는 교실 내부망에서만 `off` (점검 화면이 경고해요).
3. 리버스 프록시(앞에 다른 서버를 두는 경우) 뒤라면 그 프록시의 주소를 `security.trusted_proxies` 에 적으세요.

### §5. 수상한 활동을 기록하고 지켜봐 줘

**발견한 문제**
- 보안 기록 표(`security_events`)와 차단 표(`ip_blocks`)는 있었지만 **아무도 쓰지 않았어요**(S05, 14개 구멍): 토큰 없는 요청, 다른 사이트에서 온 요청, SQL·스크립트·경로 공격 문자열, 로그인 잠금, 관리자 엿보기, 위험한 업로드, 치트 저장, 결제 금액 조작이 하나도 기록되지 않았고, 같은 주소에서 90번 공격해도 막히지 않았어요. `/.git/config` 같은 미끼 주소도 그대로 열렸어요. → 공격자는 아무 흔적 없이, 막히지도 않고 계속 시도할 수 있었어요.
- 고치는 중에 검토로 더 찾은 것:
  - 자동 차단을 **거꾸로 쓸 수 있었어요**: 나쁜 웹 페이지가 방문자의 브라우저에 함정 주소·공격 문자열을 몰래 요청시키면, 그 방문자의 인터넷 주소(교실 전체가 함께 쓰는 주소일 수도)가 30분~24시간 막혔어요(`lib/SecurityEvents.php:389·102·32-33`, `api/trap.php:53-55` — 3장 1번). → 고침 5c5afde.
  - 저장 데이터의 통계 이름에 넣은 **제어 문자**(화면을 조종하는 숨은 글자)가 감사 기록과 `php cli/tfm.php audit` 화면에 그대로 나왔어요(`cli/tfm.php:347`, `lib/SaveValidator.php:434` — 3장 8번). → 운영자의 명령 창 글자를 지우거나 숨길 수 있었어요. 고침 72d8cb6.

**고친 내용**
- `Tfm\SecEvent::log(종류, 등급, 내용)` → 보안 기록 + 파일 로그. 종류: `csrf_fail`, `origin_mismatch`, `admin_denied`, `admin_ip_denied`, `admin_2fa_fail`, `login_locked`, `probe_sqli`, `probe_xss`, `probe_traversal`, `honeypot`, `payment_tamper`, `upload_rejected`, `save_rejected`, `https_required`, `ip_blocked`, `auto_block`. 등급은 정보(info) · 경고(warn) · 심각(alert).
- `Tfm\Firewall::check()` 가 모든 입구에서 먼저 돌아요: 막힌 주소는 403 `IP_BLOCKED` + `Retry-After`.
- **자동 차단**: 한 주소에서 아래 "세는 기록"이 **600초에 25번** → **30분 차단**, 다시 걸리면 2배씩(최대 24시간).
  - 세는 것(경고 이상만): 다른 사이트 출처의 쓰기 요청, 관리자 엿보기(관리자 화면·허용 주소 밖), 2단계 인증 코드 틀림, SQL·스크립트·경로 공격 문자열, 함정 주소, 결제 조작, 위험한 업로드.
  - 세지 않는 것: 토큰 없는 요청(`csrf_fail` — 오래 열어 둔 탭에서 흔해서 정보로만), 로그인 잠금(로그인은 따로 잠가요, §9), 저장 거부, https 요구, 그리고 **다른 사이트가 방문자 브라우저를 시켜 보낸 요청**(브라우저가 `Sec-Fetch-Site: cross-site` 로 표시한 함정·출처 불일치·공격 문자열 — 위의 "거꾸로 쓰기" 를 막으려고 정보로만 기록).
  - 서버 컴퓨터 자신과 `security.block.exempt`(예: 학교 주소)는 자동 차단하지 않아요.
- **함정(honeypot)**: 스캐너가 찾는 주소(`/.env`, `/wp-login.php`, `/phpmyadmin`, `/.git/config`, `*.bak` …)를 `.htaccess` 가 `api/trap.php` 로 보내 기록하고 빈 404 로 답해요.

- 관리자 센터 **🛡️ 보안 탭**: 오늘의 수상한 활동 수, 종류·등급·기간 필터, 주소는 끝자리를 가리고 짧은 지문으로, "이 주소 1시간 차단", 막아 둔 주소와 차단 해제, 관리자 로그인 기록, 관리자별 2단계 인증 상태. 서버 컴퓨터에서 `php cli/tfm.php security:events [개수]`, `ip:block <주소> [초] [사유]`, `ip:unblock <주소>`.
- **알림**(선택, 기본 꺼짐): 자동 차단·결제 조작 같은 심각한 일이 생기면 메일(PHP `mail()` 이 되는 서버) 또는 https 웹훅으로 알려요. 보낼 곳은 설정 파일이나 서버 환경 변수로만 정하고, 요청에 담긴 값은 절대 쓰지 않아요. 같은 종류는 10분에 한 번.
- 관련 커밋: a9eb62a · dabd5af · 5c5afde · 72d8cb6.

**테스트** — S05 **16/16** (`--apache --only S05`): `csrf_fail`, `origin_mismatch`, `probe_sqli/xss/traversal`, `login_locked`, `admin_denied`, `upload_rejected`, `save_rejected`, `payment_tamper` 가 각각 기록됨 · 함정이 404 + `honeypot` 기록 · 같은 주소의 반복 공격 → 403 `IP_BLOCKED`, 다른 주소는 정상 · **꾀어낸 방문자(교차 사이트)는 차단되지 않음** · 미끼 주소가 내장 서버와 Apache 에서 403/404 · 하위 폴더 설치에서도 함정 기록. 단위 시험 `php tests/security-unit.php`: 기록 형식·등급·홍수 상한·90일 정리·25번째에 차단·2배·24시간 상한·창 밖은 세지 않음·localhost 와 예외는 차단 안 함·"경고 이상의 공격 종류만 셈"·"알림은 기본 꺼짐, 웹훅은 https 만, 요청에서 받지 않음". `php tests/security-data-unit.php`: 제어 문자가 기록·로그·명령 창에 날것으로 가지 않음(3개).

### §6. 관리자 페이지 경로를 잠가 줘

**발견한 문제**
- 관리자 화면이 누구나 짐작하는 주소 `admin.php` 에 있었고, 비밀번호 하나로만 들어갔어요(2단계 인증 없음, 허용 주소 없음)(S06, 8개 구멍). → 관리자 비밀번호 하나만 알아내면(같은 비밀번호를 다른 곳에도 썼다면) 모든 회원 정보와 결제를 다룰 수 있었어요.
- 관리자가 아직 없을 때 "서버 컴퓨터(localhost)에서 접속하면 첫 관리자로 지정" 하는 기능이 있었는데(`lib/Core.php:367-380`, `config/config.php:78`, F4), 터널·포트 전달 프로그램 뒤에서는 **인터넷의 누구나 localhost 로 보여서** 남이 첫 관리자가 될 수 있었어요.
- 관리자 이메일 목록(`security.admin_emails`)에 적힌 이메일로 **먼저 가입한 사람이 관리자**가 됐어요 — 이메일 주인인지 확인하지 않았어요(`lib/Users.php:142-146·162`, F2).
- 쿠키 없는 방문마다 세션 파일이 생겼고(`admin.php:476-479`, F9), 로그인 화면에 버전이 보였어요(F15).
- 고치는 중에 검토로 더 찾은 것: 2단계 인증 코드를 하루 약 600번 맞혀 볼 수 있었어요(`lib/Totp.php:274-290·305-307`, 3장 4번 → 고침 52878d3). 허용 주소 밖의 방문자도 관리자 화면의 모양 파일(`admin.css`)과 "폴더 끝 `/` 붙이기" 이동은 받아서, 이름을 바꾼 관리자 폴더가 어디 있는지 알 수 있었어요(`admin/.htaccess:20`, 3장 5번 → 고침 427e52b).
- 마지막 완전성 점검에서 찾은 것: **설치 마법사가 무작위 폴더 이름을 제안하지 않아서**, 새로 설치한 서버는 운영자가 따로 바꿀 때까지 누구나 짐작하는 `/admin/` 에 있었어요 (→ 고침 743b5b2).

**고친 내용**
- 관리자 센터는 **자기 폴더** `admin/`(`index.php` + `.htaccess`)에 있고, 화면 모양은 `lib/admin.css`(웹에서 직접 안 열림)를 주소 확인 뒤에 보내요. 예전 `admin.php` 는 **없는 페이지(404)** 처럼 답하고 방문을 함정으로 기록해요.
- **폴더 이름은 자유**: `php cli/tfm.php admin:path --random` → `admin-무작위10글자`, 직접 정하기 `admin:path 이름`, 지금 이름 보기 `admin:path`. **설치 마법사가 무작위 이름을 제안**해요(기본으로 켜짐) — 새 주소는 설치 완료 화면에만 한 번 보이고, 누구나 여는 설치 화면에는 나오지 않아요. 관리자 계정으로 체험관에 로그인하면 메뉴의 관리자 센터 버튼이 알아서 새 주소로 가요(`api/auth/me.php` 가 **관리자에게만** 주소를 알려 줘요).
- **허용 주소**(`security.admin_ip_allowlist` / `TFM_ADMIN_IPS`, IPv4·IPv6·범위): 다른 주소에는 **없는 페이지와 똑같은 404** + `admin_ip_denied` 기록 — 화면, 모양 파일, 끝에 `/` 없는 폴더 주소까지.
- **2단계 인증(TOTP)**: 휴대폰 인증 앱의 6자리 숫자(RFC 6238 표준, 30초, 앞뒤 30초까지 인정, **한 번 쓴 숫자는 다시 못 씀**), 일회용 **백업 코드 10개**(해시로 저장), 비밀 키는 봉인 저장. `security.admin_2fa` = `off` · `optional`(기본, 등록 안 한 관리자에게 "켜 주세요") · `required`. 틀린 코드는 **따로 잠겨요**(처음 24시간 16번 이하, 1년 400번 이하). 휴대폰을 잃으면 서버 컴퓨터에서 `admin:2fa-reset 이메일`, 잠금만 풀기 `admin:2fa-unlock 이메일`.
- **관리자 승격**: 체험관에 로그인되어 있어도 관리자 센터는 비밀번호(+코드)를 한 번 더 물어요. 승격 = 세션 표시 + 관리자 폴더에만 보내지는 쿠키 `TFMADM`(HttpOnly · SameSite=Strict · https 면 Secure), 승격할 때 세션 번호 교체, **30분 동안 안 쓰면 다시 물어요**(`admin_idle`).
- 첫 관리자: 설치 마법사의 첫 계정, 또는 관리자가 없을 때 관리자 센터의 "첫 관리자 지정" + **설치 코드**(서버 컴퓨터에서만 볼 수 있는 일회용 코드, `php cli/tfm.php setup-code`), 또는 `php cli/tfm.php promote 이메일`. localhost 를 믿는 기능과 이메일 목록으로 관리자를 주는 기능은 없어졌어요.
- 모든 응답에 `X-Robots-Tag: noindex, nofollow`(검색 엔진에 안 나오게), `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`. 스크립트 0개. 모든 작업은 POST + CSRF + 같은 사이트 확인 + 감사 기록 + 303 이동.
- `admin/.htaccess` 에 **바로 켤 수 있는** "Require ip"(주소 제한)와 Basic 인증(브라우저 비밀번호 창) 블록이 주석으로 들어 있어요.
- 점검 화면 "🔐 관리자 페이지 잠금": 기본 폴더 이름 ⚠, 허용 주소 없음 ⚠, 2단계 인증 미등록 ⚠, 예전 관리자 화면 파일이 남아 있으면 ⛔, 설치 마법사가 공개 서버에서 열려 있으면 ⛔.
- 관련 커밋: a9eb62a · 31fe702 · 8c0af2c · 52878d3 · 427e52b · 743b5b2.

**테스트**

**운영자가 할 일** (설치 직후 순서)

### §7. 데이터베이스 질의는 파라미터 방식(SQL 인젝션 방지)으로 써 줘

**발견한 문제**

- 남은 틈: `Db::upsert` 가 열 이름을 따옴표로 감싸지 않았고(`lib/Db.php:148-180`, F14 — 호출하는 곳은 모두 코드 상수라 실제 위험은 없었어요), 몇몇 곳은 숫자(LIMIT)를 글자로 붙였고, **새로 생기는 질의를 자동으로 검사하는 도구**가 없었어요. → 나중에 누가 코드를 고치다 실수해도 알아챌 방법이 없었어요.

**고친 내용** — `upsert` 의 모든 이름을 `Db::ident` 로, LIMIT 도 값으로 넘기기(`LIMIT ?`). **`tools/sql-audit.mjs`**: 서버의 모든 PHP 에서 변수나 이어 붙이기로 만든 SQL 을 찾아 실패로 알려요. 검토한 24곳(이름은 코드 상수뿐, 숫자는 범위를 자른 정수)은 `tools/sql-audit.allow.json` 에 이유와 함께 적었어요. 결제 엔드포인트에도 인젝션 시험을 더했어요. (커밋 b58009f · 181d753)

**테스트** — S07 **7/7** (`--only S07`, MariaDB 로도): 로그인에 고전·참거짓·UNION·여러 문장 공격 18가지 → 로그인 안 되고 DB 오류도 안 보임 · 시간 지연 공격 → 지연 없음(기준 211 ms, 공격 187~332 ms) · 가입·채팅의 SQL 문자열은 거절되거나 글자 그대로 저장(표는 멀쩡) · 번호·페이지 값에 공격 → 변화 없음 · 관리자 검색 17가지 → 결과가 넓어지지 않음 · **MariaDB 에서 `SLEEP`·`; DROP …`** → 지연·피해 없음 · 이번 시험의 모든 응답에 DB 오류 글자 없음. `node tools/sql-audit.mjs` → "61 PHP files · 220 SQL statements · 24 dynamic (24 reviewed, 0 unreviewed)".

**운영자가 할 일** — 없어요. (개발자는 코드를 바꾼 뒤 `node tools/sql-audit.mjs` 가 0 인지 확인하세요.)

### §8. 환경 변수가 안전한지 확인해 줘

**발견한 문제**
- 토스페이먼츠 **문서에 공개된 예시 키가 기본값**이었어요(`lib/Toss.php:41-47`, `config/config.php:206-207`, F3). → 운영자가 키를 넣지 않아도 결제 화면이 동작하는 것처럼 보였고, 모의 결제를 끄면 시험 결제가 **진짜로 승인**되어 누구나 유료 단계를 공짜로 받을 수 있었어요. `api/sub/status.php` 가 그 키를 내보냈어요(S08).
- 설정 전체를 한 번에 점검하는 기능이 없었고, 점검 화면(`lib/Admin.php:129-310`, F18)은 모의 결제를 ⚠ 로만 알렸고 root DB 계정은 아예 보지 않았어요.
- 마지막 완전성 점검에서 찾은 것: 비밀 키를 언제 만들었는지(**키 나이**) 알려 주는 줄이 없었고, 설치 마법사가 설정 점검을 돌리지 않았어요. 그리고 `display_errors` 줄은 앱이 실행 중에 끄는 값만 읽어서 **php.ini 에서 켜져 있어도 늘 ✅** 였어요 (→ 고침 743b5b2).

**고친 내용**
- **`Tfm\ConfigAudit`**(`lib/ConfigAudit.php`): 앱 비밀 키 · **키 나이**(앱 키·데이터 키 — 만들거나 바꾼 지 1년 넘으면 ⚠ + `secret:rotate` 안내) · `config.local.php`·`secret.php` 가 다른 사용자에게 쓰기 가능한지 · 그 두 파일이 웹에서 열리는지(서버가 자기에게 물어봄) · 관리자 이메일 목록 · 관리자 계정 있음 · 데이터 폴더가 웹 루트 안인지 · HTTPS 강제 · 모의 결제/모의 AI/저장 검증 건너뛰기(공개 운영 서버면 ⛔) · 로그 상세도 · 실행 모드 · **`display_errors`(php.ini 값)** · `expose_php` · 신뢰 프록시 · CORS 목록 · 토스 키 · DB 실행 계정 · 자동 스키마 변경 · 웹 서버 이름표·TRACE · 세션 쿠키. **값은 절대 보여 주지 않고** "설정됨 / 설정 안 됨 / N일" 만.

### §9. 요청 횟수 제한을 걸어 줘

**발견한 문제**
- 몇몇 엔드포인트는 한도가 없거나 다른 것과 함께 썼어요(S09: `admin/health` 가 `admin/stats` 의 한도를 함께 쓰는데도 200, 업로드 21번에 429 없음 …). 고정된 시간 칸의 경계에서는 한도보다 1번 더 통과했어요(커밋 d7579eb 에서 고침). → 프로그램으로 짧은 시간에 수천 번 보내 서버를 바쁘게 하거나 비밀번호를 빨리 맞혀 볼 수 있었어요.
- 검토로 찾은 것: 여러 주소에서 한 계정의 비밀번호를 틀리면 **주인이 맞는 비밀번호로도 못 들어갔어요**(`lib/Security.php:156-161·172-176`, 3장 2번). → 로그인 이름(닉네임)은 공개라서 누구나 남의 계정(관리자 포함)을 계속 잠가 둘 수 있었어요. 매번 다른 가짜 세션 쿠키를 보내면 요청마다 새 세션 파일·새 한도 칸이 생겼어요(`lib/Session.php:44`, F9, 3장 6번).

**고친 내용**
- **모든 엔드포인트에 이름 붙은 한도**(`config.php` 의 `rate_limits`, 부록 A 에 표): 로그인한 사람은 계정별, 아니면 세션별 + 주소 전체 상한(×25), 로그인은 주소별, 가입은 세션별 + 주소별(`register_ip`), 결제 쓰기는 계정별, 함정·설치·결제창 복귀·웹훅은 주소별.
- 미끄러지는 시간 창(앞 칸의 몫을 올림으로 셈) → 한도 + 1 은 언제나 걸려요. 넘으면 **429 + `Retry-After`** + `data.retryAfter`(몇 초 뒤에 다시).
- 로그인 잠금 세 가지: ① 같은 주소 + 같은 계정 5번 실패 → 30초부터 2배씩(최대 1시간) ② 한 주소가 여러 계정을 60번 틀림 → 그 주소 15분 ③ 계정 전체 잠금은 **서로 다른 주소 15곳 이상**에서 틀렸을 때만, 그리고 **틀린 비밀번호에만** 적용 — 맞는 비밀번호를 넣은 주인은 어느 주소에서든 들어가요(커밋 0e4aa8a).
- 처음 보는 세션 쿠키는 이어 쓰기만 하는 요청에서 **새 세션 파일을 만들지 않아요**(커밋 3a831f4).

**테스트** — S09 **9/9** (`--only S09`): 한 계정 6번째 비밀번호 → 429 · 한 주소에서 여러 계정 → 61번 안에 429 · **여러 주소의 공격 뒤에도 주인은 맞는 비밀번호로 로그인** · 가입 21번 안에 429 · 저장 1분 46번 안에 · 채팅 1초에 2번째 거절 · 신고 1시간 11번 안에 · 가짜 쿠키를 돌려도 세션 파일이 쌓이지 않음 · 그 밖의 모든 엔드포인트가 정해진 한도 안에서 429 + `Retry-After`.

**운영자가 할 일** — 평소에는 없어요. 한 교실이 한 인터넷 주소로 많이 들어와서 "요청이 너무 많아요" 가 자주 보이면 `config/config.local.php` 에서 `rate_limits`(엔드포인트별 한도), `login.ip_max_failures`(한 주소의 로그인 실패 한도, 기본 60), `rate_limit_ip_multiplier`(로그인 안 한 요청의 주소 전체 상한 배수, 기본 25)를 늘리고, 그 주소를 `security.block.exempt` 에 넣어 자동 차단에서 빼세요.

### §10. CORS 설정을 필요한 곳만 허용하게 좁혀 줘

**발견한 문제** — 기본값은 이미 "같은 사이트만"(CORS 머리글 없음)이라 다른 사이트가 우리 서버의 답을 읽을 수 없었어요. 다만 꼭 필요한 공개 정보만 다른 사이트(예: 학교 홈페이지)에 열어 주는 **허용 목록 기능이 없었어요**(S10, 3개). → 필요해지면 누군가 `*`(모두 허용)로 열어 버릴 위험이 있었어요.

**고친 내용** — `security.cors_allowed_origins`(`TFM_CORS_ORIGINS`): 정확한 `https://호스트[:포트]` 만, `*` 는 절대 안 돼요. 그 주소에만, **읽기 전용 공개 GET 4개**(`ping`, `time`, `ranking/top`, `sub/status`)에서 `Access-Control-Allow-Origin: <그 주소>` + `Vary: Origin`. 로그인 정보(쿠키)는 같이 보내지 않고, 쓰기 요청과 그 밖의 사전 요청(preflight — 브라우저가 미리 물어보는 요청)은 403. 점검 화면은 `*` 를 ⛔ 로 알려요. (커밋 a9eb62a)

**테스트** — S10 **4/4** (`--only S10`): 기본은 어떤 엔드포인트에도 CORS 머리글 없음 · 목록의 주소만 정확히 되돌려 줌 · 비슷한 주소·다른 방식·다른 포트·`null` 은 안 됨, `*` 없음 · 로그인 정보·POST·비공개 GET·사전 요청은 언제나 안 됨.

**운영자가 할 일** — 없어요. 다른 사이트가 랭킹을 보여 줘야 할 때만 그 주소를 적으세요.

### §11. 보안 헤더를 추가해 줘

**발견한 문제** (S11, 6개): 직접 열면 안 되는 PHP 파일의 404 에 `X-Powered-By: PHP/8.3.6`(PHP 버전) · `index.html` 에 CORP 없음 · css·js 에 CSP·CORP 없음 · Apache 오류 페이지에 `nosniff`·CSP 없고 서버 서명(버전) 표시 · 모든 응답의 `Server: Apache/2.4.58 (Ubuntu)` · TRACE(요청을 그대로 되돌려 주는 방식)에 200. → 정확한 버전을 알면 공격자는 그 버전에 알려진 공격 방법을 골라 쓸 수 있어요.

**고친 내용**
- 응답 종류(API · 관리자 · 설치 · 정적 파일 · 오류 페이지)마다 **머리글 한 벌**: CSP, `X-Content-Type-Options: nosniff`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, COOP, CORP, 동적 응답 `Cache-Control: no-store`, https 면 HSTS. 업로드 사진에는 sandbox CSP.
- 모든 "직접 열기 막기" 404 에서 `X-Powered-By` 를 지워요. 정적 파일은 `.htaccess` 의 확장자별 규칙으로, 오류 페이지는 자체 `e403.html`/`e404.html`(하위 폴더 설치도)로.
- `Server` 버전과 TRACE 는 **`.htaccess` 로 바꿀 수 없는 Apache 전체 설정**이에요(Apache 가 `.htaccess` 를 읽기 전에 처리해요) → 점검 화면 "웹 서버 설정(ServerTokens · TraceEnable)" 이 운영자에게 알려요. (커밋 a9eb62a · dabd5af · 59882f6 · 690d1b9)

**테스트** — S11 **12/12** (`--apache --only S11`): 26개 엔드포인트의 104개 응답 · 관리자 로그인과 11개 화면 · 설치(열림·잠김) · 비공개 PHP 404 에 본문·`X-Powered-By` 없음 · Apache: `index.html`, css·js, 업로드 사진(sandbox CSP), mod_php 뒤의 모든 입구, 403/404 오류 페이지, 진짜 하위 폴더 설치의 404 · 서버 버전/TRACE 는 숨겨지거나 점검 화면이 알림(이 두 줄은 httpd.conf 를 바꿀 수 없는 시험 환경이라 "점검 화면이 알림" 으로 통과해요).

**운영자가 할 일** — `C:\xampp\apache\conf\httpd.conf` 맨 아래에 다음 세 줄을 넣고(또는 `conf\extra\httpd-default.conf` 의 `ServerTokens Full` → `Prod`, `ServerSignature On` → `Off` 로 바꾸고) Apache Stop → Start:
```apache
ServerTokens Prod
ServerSignature Off
TraceEnable Off
```
그리고 `C:\xampp\php\php.ini` 에서 `expose_php = Off`. 🩺 시스템 점검의 "웹 서버 설정(ServerTokens · TraceEnable)" 과 "expose_php" 줄이 ✅ 가 되면 끝이에요.

### §12. 세션 쿠키를 안전하게 설정해 줘

**발견한 문제** — 세션 쿠키(로그인한 브라우저가 들고 다니는 번호표)는 시작할 때부터 대부분 안전했어요(HttpOnly · SameSite=Lax · 설치 폴더 경로 · 엄격 모드 · 쿠키로만, S12 10/11). 빠진 것은 **관리자 승격 쿠키(SameSite=Strict)** — 관리자 센터 자체가 따로 없었기 때문이에요. 또 가짜 쿠키를 보내면 새 세션 파일이 생겼어요(§9).

**고친 내용** — 세션 쿠키 `TFMSESSID`: HttpOnly(스크립트가 못 읽음), SameSite=Lax(다른 사이트에서 몰래 못 씀), https 면 Secure, 경로 = 설치 폴더, 엄격 모드(서버가 만든 번호만 받음), 주소창 세션 번호 금지, **가입·로그인·로그아웃·권한 변경·2단계 인증 때 세션 번호 교체**, 2시간 유휴·24시간 최대(로그인 유지: 7일 유휴·30일), 브라우저 지문(User-Agent)이 바뀌면 끝. 관리자 승격 쿠키 `TFMADM`: SameSite=**Strict** · HttpOnly · 관리자 폴더에만. PHP 7.2 에는 SameSite 를 넣는 함수가 없어서 쿠키 경로 뒤에 덧붙이는 방법을 써요(4장 4.1). (커밋 31fe702 · 3a831f4)

**테스트** — S12 **11/11** (`--apache --only S12`): 쿠키 속성 · 하위 폴더 경로(내장 서버·Apache) · 가입·로그인·로그아웃마다 번호 교체, 예전 번호는 죽음 · 고정 공격(미리 심은 번호) 안 됨 · 주소·본문의 번호 무시 · 2시간(시험은 2초) 유휴 · 최대 수명(시험 3초) · 다른 브라우저의 훔친 쿠키는 로그인 아님 · 권한 변경 → 열려 있던 세션 끝 · 승격 쿠키 Strict + HttpOnly + 폴더 경로.

**운영자가 할 일** — HTTPS 를 켜면(§2) `Secure` 가 저절로 붙어요. 운영 서버(PHP 7.2)에서 한 번만 쿠키 표시를 확인해 주세요(5.3 의 7번).

### §13. CSRF 보호를 넣어 줘

**발견한 문제** — 상태를 바꾸는 요청은 시작할 때부터 세션 토큰 + 출처(`Origin`/`Sec-Fetch-Site`) 검사가 있었어요(S13 12/12). 다만 출처 머리글이 없거나 `null` 일 때도 받았고 http/https 를 비교하지 않았어요(`lib/Security.php:25-39`, F16). 새 관리자 센터의 모든 작업도 같은 보호가 필요했어요.

**고친 내용** — 모든 POST: 세션별 32바이트 토큰(`X-CSRF-Token` 머리글) + 다른 사이트의 `Origin` 이나 `Sec-Fetch-Site: cross-site` 는 토큰이 맞아도 403 + `origin_mismatch` 기록. 출처가 없거나 `null` 이면 토큰이 반드시 맞아야 해요. https 요청에 http 출처는 다른 사이트로 봐요. 관리자 센터의 모든 폼(22개 작업)도 토큰 + 같은 사이트 확인 + 303. 세션이 없는 관리자 로그인 폼은 서버에 아무것도 남기지 않는 서명 토큰을 써요(F9). 토큰은 로그인·로그아웃 때 바뀌어요. 웹훅은 문서화된 예외(토스 서버가 보냄, 세션 없음 — 대신 결제를 다시 조회하고 단계를 올리지 못함, §15). (커밋 a9eb62a · 31fe702)

**테스트** — S13 **12/12** (`--only S13`): 14개 POST 엔드포인트가 토큰 없음·틀린 토큰·다른 세션의 토큰·다른 사이트 출처·`Sec-Fetch-Site: cross-site` 를 모두 403 · 비슷한 출처(다른 포트·뒤에 붙인 이름)도 다른 사이트 · 세션 없는 POST 는 401/403 · 토큰은 머리글로만(저장 비콘만 예외) · 정상 요청은 통과, 상태를 바꾸는 GET 은 405 · 웹훅은 누구 대신 아무것도 못 함 · 관리자 폼 20개 × 위조 4가지 → DB 그대로 · 로그인·로그아웃 때 토큰 교체.

**운영자가 할 일** — 없어요.

### §14. 파일 업로드 종류와 크기를 제한해 줘

**발견한 문제** — 사진 업로드 검사는 이미 튼튼했어요(S14 14/15). 남은 것: 파일을 받지 않는 엔드포인트에 `multipart/form-data`(파일 보내기 형식)를 보내면 415 로만 답하고 기록이 없었어요 · PHP 의 그림 기능(GD)이 없으면 **원본을 그대로 저장**해서(`lib/Upload.php:84-93`, `config/config.php:161`, F8) 아이가 찍은 사진 속 **위치 정보(GPS)** 가 남을 수 있었어요 · 웹 서버 쪽 업로드 크기 제한이 없었어요(F17).

**고친 내용** — 파일은 `journal/upload.php` 만 받아요. 다른 곳에 파일을 보내면 **400 `UPLOAD_NOT_ALLOWED`** + `upload_rejected` 기록. 사진: 로그인한 사람만, **5 MB 이하**, 내용으로 확인한 종류(finfo)가 **PNG·JPEG·WEBP** 이고 그림 정보(getimagesize)와 일치, 해상도·전체 화소 상한(압축 폭탄 방지), 스크립트·HTML 이 섞인 파일 거부, **GD 로 다시 그려 저장**(위치 정보·숨긴 데이터 제거), 무작위 128비트 이름 + 강제 확장자, 하루·전체 개수 제한. **GD 가 없으면 업로드를 받지 않아요.** `.user.ini` 와 `.htaccess`: `upload_max_filesize 6M`, `post_max_size 8M`, `max_file_uploads 2`, `LimitRequestBody`(8 MB). `uploads/.htaccess`: 스크립트 실행 금지, `[a-f0-9]{32}.(png|jpg|webp)` 이름만, sandbox CSP. ### §15. 가격과 결제 금액을 서버에서 확인해 줘

**발견한 문제**

- 검토로 찾은 것(모두 고침, 3장 9~12번):

  - MariaDB 에서 한 계정의 두 결제를 동시에 승인하면 **두 번 결제됐는데 한 기간만** 더해졌어요(`lib/Subscription.php:262·378`, 커밋 05da87a).

**고친 내용**

### §19. 밖에 노출된 파일이 없는지 확인해 줘

**발견한 문제** — Apache 에서 `.git/config`, `.svn/entries`, `backup.zip`, `site.tar.gz`, `*.php~`, `*.save` 같은 남은 파일이 **그대로 내려받아졌어요**(S19). `error_log` 파일도 열렸고, 비공개 PHP 파일의 404 에 PHP 버전이 보였어요. 로그 파일 이름은 날짜로 짐작할 수 있었고, 로그의 첫 줄(직접 열면 아무것도 안 보이게 하는 보호 줄)이 동시에 쓰일 때 빠질 수 있었어요(`lib/Core.php:263-301`, F7). `.htaccess` 를 읽지 않는 서버(`php -S`)에서는 DB 파일 등이 열려요(참고). → `.git` 이 열리면 코드 전체를, 백업 압축 파일이 열리면 DB 를 통째로 가져갈 수 있었어요.

**고친 내용** — 루트 `.htaccess`: `lib/ config/ database/ data/ cli/` 전체 차단, 숨은 폴더·압축 파일·편집기 사본·`*.sqlite .sql .log .md .lock .ini .env .bak`·`config.local.php`·`error_log` 차단, 폴더 목록 끔, 하위 폴더 설치와 경로 꼼수(인코딩된 `../`, 대소문자, 끝의 점, PATH_INFO, Windows 의 `::$DATA`·짧은 이름)도 막음. 모든 비공개 PHP 파일의 직접 열기 → 본문 없는 404. 로그의 보호 줄은 언제나 먼저 써요. **`tools/exposure-audit.mjs`**: 서버 사본에 진짜 비공개 파일과 남은 파일 44개를 심고 웹으로 하나씩 요청해서, 열리는 것이 있으면 실패해요. (커밋 0ad6451 · dabd5af · 59882f6 · a9eb62a)

**테스트** — S19 **7/7** (+ 내장 서버 참고 6줄, `--apache --only S19`): `.htaccess` 없이도 비공개 PHP 는 빈 404 · Apache: 비공개 폴더 61개 파일 모두 403/404 · 진짜 DB·`secret.php`·세션·로그·잠금 파일 12개 못 받음 · 남은 파일 21개 전부 403/404 · 하위 폴더·경로 꼼수 14가지 · 폴더 26개 목록 없음. `node tools/exposure-audit.mjs --apache` → Apache 에서 열린 것 0 (내장 서버 쪽 62줄은 "`.htaccess` 를 읽지 않는 서버라면 이것이 열린다" 는 참고).

**운영자가 할 일**

2. htdocs 안에 백업·압축 파일·메모를 두지 마세요.
3. Apache 가 아닌 서버(Nginx, `php -S`)라면 반드시 `TFM_DATA_DIR` 로 데이터 폴더를 웹 루트 밖에 두세요(`server/README-SERVER.md` 의 Nginx 예시). Windows 에서는 파일 권한(0600)이 적용되지 않으니 더 중요해요(4장 R9).

### §20. 깃 기록에 새어 나간 비밀 값이 없는지 검사해 줘

**발견한 문제** — 지금까지의 모든 커밋(`git log -p --all`)에서 키 모양 값은 **토스페이먼츠 문서에 공개된 예시 키 2개**(클라이언트 키 `test_ck_D5…`, 시크릿 키 `test_sk_zX…`)뿐이었어요: 커밋 `e9e3aca`(`docs/CONTRACT.md:962`), `396fc53`(`config.php:206-207`, `Toss.php:41-42`). 이 키는 토스가 개발 문서와 공식 예제 저장소에 누구나 보라고 올린 **시험용** 키라 실제 돈이 오가지 않고, 우리 가맹점과 관계가 없어서 "유출" 이 아니에요. AWS·구글·깃허브·슬랙·스트라이프·Anthropic 키, 개인 키 파일, JWT, 진짜 비밀번호는 없었어요(gitleaks·detect-secrets·trufflehog 로도 같은 결과).

**고친 내용** — 기본값에서 예시 키를 지웠고(c671306, 문서는 576800e), 넣어도 지문으로 거절해요. **`tools/secret-scan.mjs`**: 지금 파일과 깃 기록 전체에서 키 패턴·비밀번호 대입·무작위성이 높은 글자를 찾고, 검토한 것은 `tools/secret-scan.allow.json` 에 이유와 함께(시험용 가짜 비밀번호, RFC 시험 값, 예시 키의 SHA-256 지문 …). 깃 기록은 다시 쓰지 않았어요: 여러 담당이 함께 쓰는 브랜치이고, 지울 값이 원래 공개된 값이라 안전이 더 좋아지지 않기 때문이에요. (커밋 a6d0b5e)

**운영자가 할 일** — 없어요. 키는 `config/config.local.php` 나 환경 변수에만 넣고, 저장소·문서에는 넣지 마세요. 코드를 바꾼 뒤 `node tools/secret-scan.mjs` 가 0 인지 확인.

### §21. 유출된 키는 폐기하고 새로 바꿔 줘

**발견한 문제** — 폐기할 **진짜 키는 없었어요**(§20). 다만 이번 버전 전에는 결제가 실패하면 빌링키가 로그 파일에 남을 수 있었어요(§1). 명령줄 도구는 비밀번호와 키를 명령줄 인수로 받았어요(`--pass`, `--admin-pass`, `--toss-secret`, `reset-password <비밀번호>`, F20) — 같은 컴퓨터의 다른 사용자가 실행 중인 프로그램 목록이나 명령 기록에서 볼 수 있었어요. 그리고 키를 쉽게 바꾸는 도구가 없었어요.

**고친 내용**
- `php cli/tfm.php secret:rotate [--app-key] [--data-key]`(아무것도 안 주면 둘 다): **앱 키** — 모든 사용자 로그아웃, 요청 한도·로그인 시도 기록 정리, 차단 주소 지문 다시 계산 / **데이터 키** — 봉인된 빌링키·2단계 인증 비밀 키를 새 키로 한 번에 다시 봉인(실패하면 되돌림), 그 뒤 예전 키는 지워져요. 언제 바꿨는지 기록돼서 점검 화면의 "키 나이" 가 알려 줘요. 끝나면 토스·Anthropic·DB 비밀번호·관리자 비밀번호를 바꾸는 순서를 화면에 보여 줘요(키 값은 절대 안 보여 줌).
- `php cli/tfm.php db:rotate-password --admin-user root`: 전용 DB 계정 비밀번호를 32자 무작위로 바꾸고 설정에 적어요(실패하면 되돌림).
- 명령줄은 비밀번호·키를 인수로 받지 않아요(넣으면 거절): 화면에 보이지 않게 묻거나, 다른 프로그램에서는 환경 변수 `TFM_DB_ADMIN_PASS`·`TFM_ADMIN_PASS`·`TFM_TOSS_SECRET_KEY`·`TFM_NEW_PASSWORD`.
- 토스·Anthropic 키는 **그 회사 화면에서만** 다시 만들 수 있어서 방법을 아래에 적었어요. (커밋 d768423 · c671306)

**테스트** — `php tests/security-data-unit.php`(MariaDB 포함): 데이터 키 교체 뒤 봉인 값이 같은 내용으로 열림, 예전 키 지워짐 · 앱 키 교체 뒤 세션 끝 · 실패하면 되돌림 · 명령이 바뀐 것과 외부 키 순서를 보여 주되 키 값은 안 보여 줌 · 명령줄 인수로 비밀번호·키를 주면 거절 · (MariaDB) DB 비밀번호 교체 뒤 예전 비밀번호로 접속 안 됨, 권한은 그대로.

**운영자가 할 일** (키가 새어 나갔다고 의심될 때 — 진짜 시크릿 키를 메일·메신저·zip 으로 보낸 적이 있거나 `config.local.php` 밖에 적어 둔 적이 있을 때)
1. **토스페이먼츠**: 개발자센터(developers.tosspayments.com) → 내 개발 정보 → API 키 → 시크릿 키 **재발급**(예전 키는 바로 못 써요) → 새 키를 `config.local.php` 에.
2. **Claude(Anthropic) 키**를 쓴다면: console.anthropic.com → API Keys → 예전 키 끄기(Disable/Delete) → 새 키를 환경 변수 `ANTHROPIC_API_KEY` 에.
3. **서버 키**: `php cli/tfm.php secret:rotate` → 데이터 키를 바꿨으면 **백업을 새로** 받으세요(예전 백업의 결제 수단 정보는 예전 키로만 열려요).
4. **DB 비밀번호**: `php cli/tfm.php db:rotate-password --admin-user root`.
5. 예전 서버가 `.htaccess` 없이 돈 적이 있다면(`data/` 가 웹에서 열렸을 수 있음) 3·4번을 꼭 하세요. 이번 버전 전부터 있던 `data/logs/app-*.log.php` 는 지우세요.
(XAMPP 에서는 `php` 대신 `C:\xampp\php\php.exe`, `cli/tfm.php` 대신 `C:\xampp\htdocs\metaverse\cli\tfm.php`.)

### 3.6 공격해 봤지만 튼튼했던 것

검토 담당들이 시도했지만 뚫리지 않은 것도 적어 둬요(다음 점검 때 같은 곳을 다시 볼 필요가 줄어요):
- **HTTPS 강제**: 위조한 `X-Forwarded-Proto`, `Host: …:443`, 하위 폴더 — 쓰기 요청이 https 로 인정되지 않음.
- **비공개 폴더**: `config/`·`data/` 는 폴더 전체를 막아서 Windows 의 파일 이름 꼼수(`::$DATA`, 짧은 이름, 끝의 점, 역슬래시)도 통하지 않음.
- **함정·머리글·CORS·하위 폴더 설치**: 모두 기대대로. 사전 요청(OPTIONS)은 403, 목록에 없는 출처에는 CORS 머리글 없음.
- **결제**: 다른 계정의 주문, 금액 바꾸기, 다시 보내기, 위조 웹훅, 결제 복귀 주소의 금액 바꾸기 — 모두 막힘. 토스 결제창 스크립트는 https 고정 주소 + CSP 허용 목록.
- **봉인(Crypto)**: 값마다 새 무작위 값, 위조 검사, 키 교체 뒤에도 같은 내용.
- **설치 마법사·전용 DB 계정·`player/save.php`**: 권한·역할·구독을 브라우저가 바꿀 수 없음.
- **PHP 7.2 문법**: 새 코드 전체 0 오류 (`tools/php-compat.sh`).

### 4.2 코드로는 바꿀 수 없어서 운영자만 할 수 있는 것

- **Apache 전체 설정**(httpd.conf): `ServerTokens Prod` · `ServerSignature Off` · `TraceEnable Off` (§11), `AllowOverride All` (§19), 인증서(§2).
- **PHP 전체 설정**(php.ini): `display_errors = Off` · `expose_php = Off` (§16), `extension=gd2` (§14).
- **MariaDB 설정**(my.ini)과 계정: root 비밀번호, 익명 계정·test DB 지우기, `bind-address`, `local_infile` (§1). phpMyAdmin 은 `Require local`.
- **서버 프로그램 업그레이드**: PHP · MariaDB · Apache · phpMyAdmin (§17).
- **외부 회사의 키**: 토스페이먼츠·Anthropic 키는 그 회사 화면에서만 재발급 (§21).
- **백업과 되살려 보기**, 작업 스케줄러 등록 (§1, §15).

### 5.2 결과 읽는 법

- `PASS` / `✔` = 막힘을 실제로 확인했어요. `FAIL` / `GAP` = 구멍이에요(시험 이름과 증거, 고치는 방법이 함께 나와요).
- `INFO` = 참고예요. 예: `php -S` 는 `.htaccess` 를 읽지 않아서 "그런 서버라면 이 파일이 열린다" 를 보여 줘요(R9).
- `SKIP` = 그 환경에 맞지 않아 건너뛰었어요. 예: MariaDB 로 돌릴 때 SQLite 파일 권한 검사.
- 모든 시험은 끝에 종료 코드 **0 = 모두 통과**, **1 = 실패가 있음** 을 돌려줘요. `--json 파일` 은 결과를 표로 남겨요.
- 한 컴퓨터에서 15분 안에 기능 시험을 여러 번(약 10회 이상) 돌리면 주소별 로그인 잠금(정상 동작)에 걸릴 수 있어요. 15분 기다리면 풀려요.

### 5.3 운영 서버(Windows · XAMPP)에서 — 설치한 뒤 15분

개발 환경에는 PHP 7.2·MariaDB 10.3·Windows Apache 가 없어서(4.1), 설치한 뒤 **운영 서버에서 직접** 이렇게 확인해 주세요. 명령 프롬프트에서 `php` 대신 `C:\xampp\php\php.exe`, `cli\tfm.php` 대신 `C:\xampp\htdocs\metaverse\cli\tfm.php` 를 써요.

1. **서버 점검**: `C:\xampp\php\php.exe C:\xampp\htdocs\metaverse\cli\tfm.php status` → "종합" 에 ⛔ 가 없어야 해요. 이어서 `… cli\tfm.php config:check` → 마지막에 ⛔ 가 없으면 종료 코드 0.
2. **설치 마법사**: `http://localhost/metaverse/install.php` → 설치 코드(`… cli\tfm.php setup-code`)로 설치 → 완료 화면에 새 관리자 주소와 "🛡️ 설치 후 보안 점검" 표가 보여요. 설치 뒤 같은 주소를 다시 열면 **"Not Found"(404)** 여야 해요.
3. **관리자 센터**: 완료 화면의 새 주소로 로그인 → 🔐 2단계 인증 등록 → 로그아웃 → 다시 로그인할 때 6자리 숫자를 물어보면 성공. 예전 주소 `http://localhost/metaverse/admin.php` 와 `…/admin/` 는 404 여야 해요(이름을 바꿨다면).
4. **🩺 시스템 점검** 탭: "PHP 7.2" ⚠(업그레이드 권고)는 정상이에요. "웹 노출"·"🗄️ DB 계정"·"🔐 관리자 페이지 잠금" 줄에 ⛔ 가 없어야 해요(DB 계정 줄은 MariaDB 10.3 의 권한 글을 읽어요 — 4.1).
5. **체험관**: `http://localhost/metaverse/` 에서 회원가입 → 저장 → 채팅 한 줄 → 로그아웃 → 다시 로그인했을 때 진행이 그대로면 성공.
6. **머리글**: 명령 프롬프트에서 `curl.exe -sI http://localhost/metaverse/index.html` → `Server: Apache` 뒤에 버전이 없어야 해요(§11 의 세 줄 뒤). `curl.exe -si -X TRACE http://localhost/metaverse/` → `405`.
7. **세션 쿠키 (PHP 7.2 만의 길)**: 브라우저 개발자 도구(F12) → Application(또는 저장소) → Cookies 에서 `TFMSESSID` 가 **HttpOnly · SameSite=Lax**, 관리자 센터의 `TFMADM` 이 **SameSite=Strict** 인지 봐 주세요. 이 길은 개발 환경(PHP 8.3)에서 실행되지 않았어요.
8. **HTTPS**: 인증서를 단 뒤 `http://내도메인/metaverse/` 로 열면 `https://` 로 바뀌어야 해요.
9. **결제**: 내 `test_` 키로 2배 단계를 한 번 결제 → 관리자 센터 ⚡ 구독 탭에 기록이 보이면 성공. 토스 개발자센터에서 취소하면 웹훅으로 단계가 내려가요.
10. **작업 스케줄러**: 다음 날 "마지막 실행 결과" 가 `0x0` 인지(`sub:renew`, 백업). `config:check` 를 예약했다면 `0x1` 은 ⛔ 가 있다는 뜻이에요.
11. 이상한 점이 있으면 화면의 오류 번호(`rid`)로 `data/logs/app-날짜.log.php` 를 찾아 개발자에게 보내 주세요(로그에는 비밀 값이 없어요).

## 부록 B. 운영자 점검표 (전체 순서)

**설치하고 나서 한 번** (중요한 순서)
1. **HTTPS 인증서** 설치 (§2, `docs/SERVER-INSTALL-KO.md` 6장).
2. **관리자 센터 주소 바꾸기**: 설치 마법사의 "아무도 모르는 이름으로 바꾸기"(기본으로 켜짐), 또는 `php cli/tfm.php admin:path --random` (§6).
3. **2단계 인증**: 관리자 센터 → 🔐 탭, 모든 관리자가 등록하면 `security.admin_2fa` 를 `required` 로 (§6).
4. **관리자 허용 주소**: `security.admin_ip_allowlist`(또는 `TFM_ADMIN_IPS`) (§6).
5. **DB 잠그기 점검표**: root 비밀번호, 익명 계정·test DB 지우기, `bind-address`·`local_infile`, phpMyAdmin 은 서버 컴퓨터에서만 (§1).
6. **토스페이먼츠 내 키**, 웹훅 주소, `test_` 키로 한 번 결제 (§8, §15). 키가 없으면 결제는 "설정 필요" 로 꺼져 있어요.
7. **웹 서버 설정 세 줄 + PHP 설정 두 줄**: httpd.conf `ServerTokens Prod`·`ServerSignature Off`·`TraceEnable Off`, php.ini `display_errors = Off`·`expose_php = Off` (§11, §16). `extension=gd2` 도 (§14).
8. **데이터 폴더를 웹 루트 밖으로**(가장 안전): 환경 변수 `TFM_DATA_DIR` (§19).
9. **작업 스케줄러**: 날마다 `sub:renew` 와 백업(DB + `data/secret.php` 를 함께, htdocs 밖에) (`docs/SERVER-INSTALL-KO.md` 8장).
10. 이번 버전으로 올리기 **전부터 있던 로그 파일**(`data/logs/app-*.log.php`) 지우기 (§1, §21).
11. 5.3 의 확인 순서(15분).

**매주** — 🛡️ 보안 탭에서 같은 주소가 계속 보이는지(§5), 🚨 신고·채팅 탭의 자동 숨김(R4).
**매달** — 🩺 시스템 점검(또는 `config:check`)의 ⛔ / ⚠ · 백업을 다른 PC 에서 되살려 보기 · 작업 스케줄러의 "마지막 실행 결과" · 감사 로그의 `save_rejected`(R12).
**매년(또는 키 나이 ⚠ 때)** — `php cli/tfm.php secret:rotate` → 백업 새로 (§8, §21).
**사람이 바뀔 때** — 떠나는 사람의 2단계 인증 `admin:2fa-reset`, 권한 `demote`, 허용 주소에서 빼기, 그 사람이 키를 알았다면 `secret:rotate`·`db:rotate-password`·토스 시크릿 키 재발급 (§6, §21, `docs/HANDOVER.md` §18).
**서버 프로그램** — PHP 8.2+·MariaDB 10.11+ 로 옮길 계획 (§17).
